# Meta 广告诊断与落地页整改

交付可执行的链路诊断：异常事实 → 缺什么资料、在哪里取 → 可检验原因 → 商品内容／具体页面／流程调整 → 负责人和验收。

## 输入与边界

- 先使用已提供的文件、截图、可访问历史资料和已连接账户。表格中的图片、批注或素材截图也可能包含广告操作依据；无法读取要列缺口。不能声称看过未取得的完整对话或账户。
- 先确认业务目标（购买或合格询盘）、市场、商品与价位、实际 URL、观察期和经济约束。只追问会改变行动的缺项；资料不足先形成取数单和假设，不编造数值。
- 本技能将证据转成诊断和可审阅整改。广告预算、受众、Feed、商品、追踪及主题的实际写入需有该操作的用户授权；已有明确授权则继续，无需重复询问。试运行不要求真实支付或发送客户消息。
- 分类为 `growth/paid-media`；资料在本技能目录内按需读取，真实项目数据留在用户批准的项目资料位置。

## 执行

### 1. 建立真实路径

阅读 [references/routes-and-evidence.md](references/routes-and-evidence.md)。把实际展示平台、版位、用户关系／意图、优化目标、素材主张、广告 ID、真实最终 URL 和商品／变体分开记录。平台、目录广告、再营销、红人内容不是同一个分类维度。

以已知稳定 ID 连接资料，记录一广告多 URL／多商品的关系。无法分配到具体路径的花费留在广告层，不平均摊成页面成本。广告看到后通过品牌搜索或直接访问回站，需要另列“观察到的回访来源”和“未确认的广告影响”。站内即时体验、消息和原生表单等路径按实际步骤分析，不套直接网站漏斗。

### 2. 验证资料是否支持判断

按需阅读 [references/data-map.md](references/data-map.md) 的 D 编号取数入口和 M 编号指标规则。先取 D01 广告表现、D03 素材去向、D05 站内来源、D07 会话漏斗及 D09 订单；询盘业务用合格线索与后续销售记录替代交易漏斗。只补与当前异常有关的资料。

统一日期、时区、币种、归因窗口、转化成熟时间及事件／用户／会话／商品单位。缺失、受限、未采集、真实零值分开。导出数据与截图保留来源和覆盖范围；聚合数对不上先解释差异。

无法识别广告 ID 或页面版本时缩小结论范围；不要用新的追踪设置伪造历史映射。资料有缺陷时阻断依赖它的结论，仍可推进其他有依据的工作。

### 3. 从损失步骤定位原因

按异常读取 [references/diagnostic-playbook.md](references/diagnostic-playbook.md) 对应 P 编号，先检查流量构成变化，再看可比组内的行为差异。

每项判断写清：观察事实、主要假设、至少一个会改变决策的替代解释、验证办法。分别标记：

- **流量／素材筛选**：实际需求、市场、价位或使用条件不匹配。
- **广告与页面衔接**：点入后的商品、主张、价格或下一步与广告预期不一致。
- **商品内容**：适配条件、证据、差异、包含物或限制未解释清楚。
- **用户体验／技术**：信息难找、加载失败、选择困难或动作无法完成。
- **商品／交易条件**：用户理解后仍不接受价格、交期、配送、产品本身。
- **测量／归因**：缺失、重复、错误范围或不可比统计造成表象。

允许多因素和原因未知；不要强行三选一。高 CTR、低 CPM、高频次、高 ROAS 均不能单独证明上述任何原因。

### 4. 形成精确整改

每项任务使用 [assets/diagnosis-task.md](assets/diagnosis-task.md)，只填写有依据的动作。写明实际广告／商品／变体 ID、URL、模块／字段、修改前后和事实依据。内容应回答广告触发的具体疑问，不默认重做整页。

区分影响范围：产品字段、单页模板、共享 section、应用、目录 Feed、购物车或支付环节。先定位实际内容来源，尤其避免修改共享模板波及其他商品。价格／运费不被接受时先评估经济性，不用文案掩盖交易条件。

### 5. 按结果验收

- 优先级：**BLOCKER** 为已证实交易阻断、错链或妨碍判断的重大测量缺陷；**SHOULD FIX** 为有证据的高影响匹配／承接问题；**OPTIONAL** 为不阻断当前决策的进一步细分。优先级不代表原因已经确认。
- 已复现错误用相同设备、链接、商品与操作验证修复；内容或流量假设尽量使用同质流量的对照，记录并发变化。
- 试验预先定义主要指标、统一分母、商业保护指标、样本与时长依据及损失停止条件。不设跨行业统一 CTR、频次、测试天数或预算变动规则。
- 电商同时看购买、贡献利润／净收入与退款；询盘看合格率、合格线索成本及成熟后的销售结果。微转化仅作为定位线索。
- 结论写“支持／不支持／样本不足／受混杂影响”。只证明技术修复时不能声称已提高销售；平台归因和前后增长不能单独证明增量。

## 交付与完成标准

按任务规模提供简短诊断表或详细文件：路径映射、按优先级的异常、资料需求与入口、整改任务、验收与未知项。无原始数据时明确为方法或待验证方案。

每个建议必须能追到证据或明确的验证任务，并指出商品内容和页面动作是否适用。不要为了显得完整而给每种异常都安排改页面。渠道菜单和机制会变化：需要当前设置时查官方资料或账户实况；参考文件中的核实日期不代表已验证用户账户。
