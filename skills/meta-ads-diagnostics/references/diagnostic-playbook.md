# Meta Ads 诊断：从问题到整改

配套：`data-map.md` 提供D01—D14取数入口与M01—M16指标规则。本手册的P01—P17为待验证问题类型，不代表对某账户已经作出诊断。

## 最小执行顺序

1. 明确商业目标、转化路径、经济约束与可容忍损失。网站购买、站内表单、消息及B2B项目不能共用一套成功指标。
2. 检查D04/M16与关键业务结果能否核对。先修重大测量错误与交易阻断；不要因追踪正常就假定归因准确。
3. 用D01/D03/D05/D07/D09找出有量级且可信的断点，再选择下面最少的P类型补证。不要一次拆到所有年龄×国家×版位×素材组合。
4. 同时检查流量构成改变和同组效率改变。平台、版位、受众关系、素材承诺、实际URL、商品/变体与页面版本分别记录。
5. 每个问题至少列一个会改变结论的替代解释；没有证据时下一动作是取数/复现/对照。复现故障可直接支持技术原因，观察相关性不能单独证明商业因果。
6. 形成一项可复查整改：具体对象、before/after、证据、负责人、验收主指标、商业保护指标、观察方法和回滚条件。批量发布/改预算/安装追踪必须遵守用户现有授权范围。

## 分类与优先级

| 类别 | 可检验的问题 | 典型对应动作 |
|---|---|---|
| 流量匹配 | 来的人是否符合服务地区、用途、规格、预算及需求阶段？ | 在素材中明确条件；检查目标、交付、人群和版位。单凭低CPM或高跳出不能下结论 |
| 广告到页面衔接 | 用户实际看见的商品/承诺是否在实际到达页兑现？ | 修正链接/默认变体；让首屏和广告内容、价格条件一致 |
| 商品内容 | 用户需要的事实与证据是否缺失或含糊？ | 补适用性、尺寸/性能、包含物、案例、评价与限制，全部有事实依据 |
| 页面/操作体验 | 内容是否找得到，选择、加购、付款是否正常？ | 调整信息位置、控件、加载、反馈与错误处理 |
| 产品/交易条件 | 用户已经理解但不接受价格、费用、交期、功能或售后？ | 评估真实产品、套装、定价、履约及服务条件；不能靠排版解决经济不匹配 |
| 测量/关联 | 数据是否漏记、重复、错配、口径不同或不可关联？ | 修集成或口径；保留unknown和不可恢复历史，不用填零掩盖问题 |

- **BLOCKER**：证据已确认的交易阻断、错误去向、重大测量错误或实际商品承诺错误，阻碍可靠诊断/成交。先确定影响范围再修复。
- **SHOULD FIX**：有支持证据且影响实质的流量匹配、信息或操作问题，建立最小验证与整改。
- **OPTIONAL**：当前决策用不到的精细分组、额外事件、更多实验或页面美化；主问题解决后再做。

一个问题可跨类别，但必须分别写出证据和责任，不把所有低转化都归给页面。相邻步骤机会量可能重叠，不能相加承诺总收益。

## P01—P17 问题矩阵

### P01 CPM上涨或站外点击率下降

- **取数：** D01、D02、D03、D14（位置、字段、粒度见data-map）。
- **判断与反证：** 先拆国家、版位、素材和日期，区分流量占比变化与同组效率变化。频次上涨本身不证明疲劳。 同组出站CTR下降可能来自素材、用户构成或竞价环境；用D14排除促销、库存和价格改变。A+或Manual名称不构成好坏证据。
- **商品内容动作：** 若素材卖点不清，明确用途、适合的人、真实效果与条件。
- **落地页/流程动作：** 只有进站后指标也变差，才同时检查对应页面。不要仅因CPM上涨重做页面。
- **责任与验收：** 投手。比较同口径站外点击成本、购买/合格询盘成本及量级。 在可比组中验证新素材；如果仅CPM变化而最终单位经济稳定，继续观察，不自动关停。

### P02 站外点击多，落地页浏览少

- **取数：** D01、D02、D03、D05、D11（位置、字段、粒度见data-map）。
- **判断与反证：** 用实际广告链接在对应设备和应用内浏览器复现。核查重定向、加载、同意机制与标签，差额不全是流失。 LPV与出站点击并非同单位用户漏斗；先核实网站直达路径和分母，再解释比例。GA4缺口可能只是同意或记录差异。
- **商品内容动作：** 确认素材中价格/商品真实，排除误导点击。
- **落地页/流程动作：** 修复错链、过多跳转、首屏大图/视频阻塞、弹窗和脚本加载。
- **责任与验收：** 开发＋投手。实际链接可用；同来源到达监测改善，购买效率不恶化。 用真实广告路径复现；将成功加载、事件是否记录分开验收，不能以补发事件冒充体验改善。

### P03 到达正常，商品探索很少

- **取数：** D03、D05、D06、D13（位置、字段、粒度见data-map）。
- **判断与反证：** 逐条对照素材承诺和首屏。按国家、设备、来源可比条件检查，不把跳出率直接当页面质量。 没有view_item事件可能是未采集；集合页直接加购、快捷支付和服务询盘也可能绕过标准商品路径。
- **商品内容动作：** 首屏明确广告同款、解决的问题、实际价格和关键限制。
- **落地页/流程动作：** 广告展示整套场景时测试对应专题/集合页；单品广告直达对应商品。
- **责任与验收：** 运营＋投手。商品探索和有效购买改善，不以停留变长单独验收。 先证明探索事件覆盖相关页面；比较页面匹配改动时保持流量条件可比，观察有效购买/合格询盘。

### P04 同一页面，不同素材流量差异大

- **取数：** D01、D02、D03、D05、D09（位置、字段、粒度见data-map）。
- **判断与反证：** 先控制国家、设备、新老访客、价格与日期。用明确价格/适用条件的素材验证筛选效果。 广告系统选择的不同人群会造成组间差异；仅凭同URL不能证明素材导致低质流量。
- **商品内容动作：** 补充价位、使用门槛、适用/不适用场景；避免靠模糊承诺吸引错误需求。
- **落地页/流程动作：** 保持主要页面版本稳定做素材试验，避免同时大改页面导致原因不清。
- **责任与验收：** 投手。点击可能下降，但有效购买或合格线索成本改善。 先保持页面稳定；筛选信息的实验预先记录目标。不得把点击下降单独判为失败或成功。

### P05 集合页访问多，商品点击少

- **取数：** D05、D06、D10、D12、D13（位置、字段、粒度见data-map）。
- **判断与反证：** 检查商品列表是否被看到，筛选使用、无结果搜索和卡片点击。没有埋点时先做任务式走查。 商品点击少可能因卡片直接加购、列表未曝光、埋点缺失、缺货或价格不接受。
- **商品内容动作：** 商品卡补款式差异、用途、真实起价、供电/规格等决策信息。
- **落地页/流程动作：** 把广告同款/同场景商品放在相关区域；增加必要筛选，避免无关类目干扰。
- **责任与验收：** 运营。列表曝光后的商品选择改善，同时检查购买和新客价值。 有列表曝光证据时才计算曝光后选择；有直接加购时将其作为另一有效路径，不迫使用户多点一步。

### P06 规格/评价反复查看，加购少

- **取数：** D06、D10、D12、D13（位置、字段、粒度见data-map）。
- **判断与反证：** 结合咨询原话与操作回放判断是认真比较还是看不懂；不能仅凭停留长认定信任不足。 用户认真比较、适配困惑、可信度不足、交易条件不接受及页面操作障碍需要分开。
- **商品内容动作：** 补尺寸参照、适配条件、安装示意、包含/不包含项、真实案例及评价。
- **落地页/流程动作：** 把最常被追问的信息移到选择与CTA附近；保持关键答案可见。
- **责任与验收：** 运营。相关疑问减少，变体选择与加购改善，并观察购买。 优先解决有客服原话/任务走查支持的疑问；只使用可证明的规格、效果和评价，监控对应退款原因。

### P07 反复切换变体，选择后退出

- **取数：** D06、D10、D12、D13（位置、字段、粒度见data-map）。
- **判断与反证：** 核查选项含义、价格跳变、缺货组合和错误提示；按实际变体ID对照而非仅用产品标题。 先核对item_variant是否真实variant ID；价格跳变可能是合理不同规格价格，也可能错误或不透明。
- **商品内容动作：** 写清颜色、尺寸、功率、供电、套装数量、单件/整套价格及适用差异。
- **落地页/流程动作：** 增加必要对比，清楚标记不可售组合；默认选择必须与广告及库存相符。
- **责任与验收：** 运营＋开发。选择失败下降，成功选择到加购改善；退款不增加。 按受影响变体完成选择—加购—购物车价格核对；以错误率、成功动作及退款共同验收。

### P08 点击加购按钮，但成功加购少

- **取数：** D04、D10、D13（位置、字段、粒度见data-map）。
- **判断与反证：** 区分add_to_cart_attempt（示例自定义）与成功add_to_cart，按设备复现。成功事件必须在真实加购成功后发出。 按钮点击不是加购成功；脚本重复事件、售罄、请求错误和必选项缺失是竞争解释。
- **商品内容动作：** 若缺必选项导致失败，补清晰的选择说明。
- **落地页/流程动作：** 修复变体校验、购物车请求、按钮遮挡、加载与库存同步；让失败原因可见。
- **责任与验收：** 开发。可复现问题消失，成功率改善；重复事件未增加。 成功事件对照真实购物车状态；无需等待长期实验即可修复复现明确的交易阻断，但修后监控回归。

### P09 加购尚可，进入结账偏低

- **取数：** D07、D10、D12、D13（位置、字段、粒度见data-map）。
- **判断与反证：** 先用正确的顺序漏斗。检查总价、套装数量、运费预期、购物车更新与结账按钮。 Shopify reached checkout指结账中已有用户输入，不能直接用GA4 begin_checkout替代。快捷支付与开放漏斗需单列。
- **商品内容动作：** 提前解释总价构成、套装数量、配送范围与预计交付；优惠规则说清。
- **落地页/流程动作：** 改善购物车数量/变体修改、费用展示和结账入口。交易条件不被接受时交运营评估。
- **责任与验收：** 运营＋开发。加购后结账的分步完成率改善，购买/利润不恶化。 内容缺失补解释、难找到改位置、运费本身太贵评估交易条件；分别归责，不能统称页面不行。

### P10 开始结账正常，购买减少

- **取数：** D07、D08、D10、D14（位置、字段、粒度见data-map）。
- **判断与反证：** 按付款尝试失败、配送/地址、库存、优惠和原因未知分类；无错误记录不代表没有障碍。 弃单记录未覆盖所有离站者；付款尝试数不是人数。未记录错误的原因保留未知。
- **商品内容动作：** 在购买前说明配送限制、交期、税费与优惠适用条件。
- **落地页/流程动作：** 修复已证实的支付、3DS、地址、库存或优惠错误；不为提高转化关闭风控。
- **责任与验收：** 开发＋支付/客服。特定错误减少，结账完成改善；保留未知原因占比。 按同一结账记录去重或明确尝试粒度；修复已证实问题并保留风控，不用总弃单率证明某支付方式失败。

### P11 订单增加，但客单价或利润下降

- **取数：** D01、D02、D03、D09、D10（位置、字段、粒度见data-map）。
- **判断与反证：** 按成交SKU、套装、新老客户、折扣和退款拆解，区分商品结构变化与同款降价。 AOV变化可能是商品结构、折扣、退款、新老客或数量变化；收入增加不等于利润增加。
- **商品内容动作：** 明确高价值产品差异、套装内容和组合收益；不可用夸大价值代替解释。
- **落地页/流程动作：** 让合适的套装/配套产品易选，价格透明。若流量偏低价需求，先调整素材筛选。
- **责任与验收：** 运营＋投手。净销售/贡献利润和有效新客改善，不只追AOV。 以定义明确的贡献利润和获客质量验收；无法取得成本时给敏感性范围，不能宣称盈利。

### P12 目录广告商品点击后表现差

- **取数：** D01、D03、D06、D10（位置、字段、粒度见data-map）。
- **判断与反证：** 核对广告展示商品、目录ID、站内商品/变体ID、售价、库存、落地URL。广告ID不等于商品ID。 目录item/Shopify product/variant/GA4 item_id可能不是相同ID；多卡片或动态组合不能由广告总量反推SKU成本。
- **商品内容动作：** 统一目录与商品页的标题、属性、图片、价格与可售规格。
- **落地页/流程动作：** 修复目标链接和默认变体；多个商品不能凭一条广告总数推断各SKU花费。
- **责任与验收：** Feed负责人＋运营。商品映射准确，错款/价差减少，商品级结果改善。 实际展示/点击样本与ID映射核验；只有存在可用商品级交付和结果关联时才报告该粒度成本。

### P13 Meta ROAS很好，实际新增价值不明显

- **取数：** D01、D04、D05、D09（位置、字段、粒度见data-map）。
- **判断与反证：** 对齐日期、归因窗口、点击/浏览归因、币种、退款及新老客定义。平台归因不等于增量。 自然回访、跨设备、浏览归因、时间口径和模型差异可同时存在；高ROAS本身不证明抢归因，也不证明增量。
- **商品内容动作：** 只有证据显示产品理解问题才改内容；不根据归因差额盲目改详情页。
- **落地页/流程动作：** 保留页面版本，先修口径与订单关联。增量判断需有对照设计。
- **责任与验收：** 投手＋分析。差异可解释；以真实订单结构与有对照的商业结果评价。 先解释口径，再采用可实施对照。没有对照仅报告平台归因与经营结果，不宣称关停后的变化就是增量。

### P14 某设备/地区明显掉队

- **取数：** D02、D05、D07、D08、D10、D11（位置、字段、粒度见data-map）。
- **判断与反证：** 先检查该分组量级、语言币种、配送资格、支付和性能；组间产品/客户差异需控制。 国家/设备分组中商品、客群、支付和转化成熟度可能不同；低样本和缺失细分不可当0。
- **商品内容动作：** 补当地语言、单位、币种及适配要求，明确不可配送地区。
- **落地页/流程动作：** 修移动端遮挡、字体、选择控件与应用内浏览器兼容；配送/支付问题按地区处理。
- **责任与验收：** 开发＋运营。受影响分组的对应步骤恢复，其他分组无明显回归。 修复需明确到受影响地区×设备×URL；若无兼容数据组合，不能把几份分组表拼成虚假交叉明细。

### P15 购买后退货/咨询集中在预期落差

- **取数：** D03、D09、D10、D12（位置、字段、粒度见data-map）。
- **判断与反证：** 按SKU/变体与退款原因，回看广告和页面版本。客户反馈是证据，不能把退款全归为流量差。 退款也可能来自缺陷、破损、履约或用途不符；内容修正不能代替真实产品/交付问题整改。
- **商品内容动作：** 增加真实尺寸、材质、亮度/效果、用途限制及安装要求；修正不实或含糊承诺。
- **落地页/流程动作：** 将关键限制放到决策前，更新商品卡和详情；必要时调整商品本身。
- **责任与验收：** 产品＋运营。相关退款/售后原因占比下降，同时监控净收入与获客。 使用成熟订单批次及一致退款观察期；按原因的退款数/适当订单基数，不能只比较未成熟的新订单。

### P16 事件或转化率突然跳变

- **取数：** D01、D04、D05、D07、D09、D14（位置、字段、粒度见data-map）。
- **判断与反证：** 对照主题/应用/追踪变更日期，查重复、丢失、transaction_id、金额币种。事件总量不是广告归因量。 测量变更和真实销量变化可能同时发生；同意变化、重复集成、币种错误、支付返回也是候选原因。
- **商品内容动作：** 先保留产品内容，除非另有明确错误。
- **落地页/流程动作：** 修追踪或技术故障，避免重复安装追踪；不能把未知漏采补成零。
- **责任与验收：** 分析＋开发。事件抽查与订单可核对，异常原因和不可补回历史标清。 真实订单—事件抽查—归因报表分三层核对；标出不可回补的历史段，禁止补零伪造历史正常。

### P17 询盘多，但合格项目少

- **取数：** D01、D03、D12、D13（位置、字段、粒度见data-map）。
- **判断与反证：** 与CRM/客服按同一lead_id核对预算、数量、地区、用途、有效联系方式和后续阶段。 Instant Form/消息广告未必经过网站；线索质量低可能是条件表达、表单、销售响应或合格定义变化。
- **商品内容动作：** 广告与服务页讲清可做范围、必要条件、交期与项目资料。
- **落地页/流程动作：** 优化表单字段和下一步说明，减少无意义字段；按合格线索衡量。
- **责任与验收：** 投手＋销售。合格询盘成本与后续成交改善；提交数仅辅助。 按lead_id保留提交、接触、判定、报价、成交时间及未知状态；按成熟线索批次评价，未跟进不等于不合格。

## 每项整改的交付要求

以下字段写在任务记录中；未取得事实保留空白/未知，不把方案写成完成报告。

| 字段组 | 必填内容 |
|---|---|
| 定位 | P编号；广告ID与素材版本；真实落地URL/版本；商品、变体及目录ID映射；网站/表单/消息路径 |
| 范围 | 日期、时区、币种、转化成熟期；国家、设备、版位、客户关系、产品、价格、库存/促销条件 |
| 事实 | 原始计数、比率分子分母、单位、数据源；D编号和导出/截图位置；缺失项及其影响 |
| 解释 | 主要假设；至少一个替代解释；证据等级：事实、假设、复现/对照支持；不能证实的部分 |
| 整改 | 精确字段/页面模块/控件/配置；修改前后；所依事实；负责人；必要权限和预计工作量 |
| 验收 | 断点主指标；购买/合格线索、贡献利润、退款等适用保护指标；样本与观察方法；可接受损失 |
| 执行证据 | 生效时间、版本、同步变更；复现步骤或实验曝光；结果计数、比率和对照；影响范围 |
| 结论 | 支持/不支持/样本不足；保留/继续验证/回滚；回滚触发条件与恢复版本 |

“已完成”至少满足：资料可追溯、口径一致、假设经过适当验证、改动可复查、验收有证据且关键保护指标未恶化。仅修复技术故障时可报告功能验收通过，商业影响仍待观察；样本不足不得提前判定增长。

## 不固化为技能规则的观点

- 不把A+与Manual分别写成必然稳定与必然更高上限；以当前可验证功能、约束和实际试验结果决定。
- 不把Bid Cap写成CPA保证，不按固定CPM、频次或天数开关广告。
- 不把目录/再营销高ROAS一概视为抢归因，也不把它视为新增价值证明。
- 不从CTR高、停留长、低CPM或GA4/Meta数字差异直接反推用户心理或故障。
- 不将任何模板里的示例事件视为账户已埋点，不以方法设计授权实际变更网站、预算、追踪或付款流程。
