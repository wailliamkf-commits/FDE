# 真实路径、证据与行动边界

这是在广告诊断手册基础上新增的执行约束，不是某个账户的实测结论。

## 把“从哪里来”拆成独立维度

| 维度 | 应记录什么 | 避免的混淆 |
|---|---|---|
| 实际展示平台与版位 | 报表实际返回的平台、Feed／Reels／Stories 等版位 | 广告由 Facebook 身份发布不等于所有曝光发生于 Facebook；不预设账户有哪些可用平台 |
| 付费性质与观察到的入口 | 带标签的广告点击、自然社媒、合作创作者自然链接、搜索回访、直接访问、未知 | facebook referral 不自动等于付费；direct 不等于没有受过广告影响 |
| 用户关系与意图 | 是否已访问、已购买、项目采购；对问题／方案／产品的认知及证据 | Meta 受众配置是投放输入，不是每个到站用户真实意图的证明；新访客不等于新客户 |
| 投放目标与优化事件 | 实际目标、事件、归因设置、受众控制或建议 | 买点击的目标不能只用点击量验证购买意图；不假定自动化或手动受众必然更优 |
| 素材与承诺 | ad ID、版本、图片／视频／文案、价格、场景、适用条件、CTA | 目录是格式／投放方式，不能直接等同再营销；合作广告也不能替代流量意图判断 |
| 点击路径与目的地 | 点击 URL、站内中间页、跳转后的最终 URL、变体、语言、实验版本 | 预览 URL 不保证等于所有实际展示版本；不要把中间站内承接步骤当页面丢失 |
| 商业结果 | 成交商品、合格项目、客户历史、退款、净销售与成本 | 广告归因的购买价值不等于实际净收入、利润或增量 |

只展开能改变当前决策的维度，避免将少量订单切成过多小组。

## 路径映射最小字段

`source_evidence / observed_at / account_timezone / currency / ad_id / creative_version / publisher_platform / placement / optimization_event / audience_context / claim / click_url / final_url / lp_version / catalog_item_id / analytics_item_id / store_product_id / store_variant_id / join_status`

缺少某字段写未知，不用广告名称猜 ID。命名可读性有用，但名称可变，不作为唯一主键。

一广告多卡片、多商品、多 URL 时：保留一对多映射及生效时间；广告总花费只存一次；页面的会话或商品行为按各自数据源记录。没有对应分摊依据就不算逐页 CPA／ROAS。对同一维度分组的数据先校核总量，不把国家、设备、版位三张独立细分表相加。

规范化 URL 时保留原值；聚合时可以剔除经确认仅用于追踪的参数，保留影响商品、变体、地区、内容或实验的参数。动态参数使用账户当前支持的字段；不在未验证时给出承诺可用的整串宏。

## 原因判定需要的对照

| 候选原因 | 有价值的比较或复现 | 仍然不能据此推断 |
|---|---|---|
| 流量或素材筛选 | 同一页面版本、相近市场／设备／商品条件下，比较来源或素材的人群构成与后续行为；用明确价格／适用限制的新素材验证 | 组间差异仍可能来自系统分配及未观察人群特征；点击率下降不必然是坏事 |
| 广告与页面错配 | 把实际素材承诺逐条对照实际到达页面，复现错款、价格差或承诺缺失 | 发现错配不等于所有损失都由它造成 |
| 内容解释不足 | 客服、页面交互与任务式观察显示具体疑问未解决，再测试对应信息 | 长停留／反复看评论不能单独证明不信任 |
| 体验故障 | 在受影响设备／应用内浏览器重现选择、加购或支付失败 | 单次走查成功不等于所有设备均正常；无错误记录也不等于用户没遇到困难 |
| 交易条件不接受 | 同一商品的费用、交期、资格与真实反馈对照，评估可行修改 | 运费高不是一律降运费；必须算订单贡献与履约成本 |
| 测量错误 | 事件触发与真实业务动作对照、去重 ID、订单与金额校核、变更时间 | 追踪恢复不等于商业转化提升；失去的历史细分不能补成事实 |

先区分“运费未解释”“运费说明难找”“运费太贵”“地址无法提交”：分别对应内容、体验、交易条件、技术。三类用户问题可作为主分类，但测量与商业条件要保留为单独原因。

## 经济性和阶段

有成本资料时用一致订单口径算广告前贡献：净商品销售收入（扣折扣与退款，税费不混入收入）＋保留的运费收入－商品成本－履约／配送成本－支付及其他随订单发生的费用。成本账中已经包含的退货损失不能再扣一次。广告后贡献再减广告花费。未取得成本时只能报告收入，不能声称盈利。

可以用广告前贡献估计获客可承受范围，但只有说明订单／客户单位、复购假设、退款成熟期及目标保留利润后才可给数。没有可核验的复购贡献，不用假想 LTV 放宽亏损。

冷启动优先确认真实需求信号及链路可用；验证期围绕素材主张或页面假设做有边界的试验；扩量期看新增量的边际成本与订单质量；成熟期看获客、留存、净收入和对少数素材／老客的依赖。阶段不自动决定必须采用某种受众、Bid Cap、目录或预算结构。

## 结论与证据标记

- 事实：来源、日期、粒度可核对的观察或已复现行为。
- 假设：可解释现象，但替代原因尚未排除。
- 估算：列出公式、假设和区间；机会量不是会追回的承诺订单。
- 建议：说明目标、证据、成本和失败条件。
- 因果／增量：需要合适对照及可比性；前后比较和平台归因只提供线索。

截图中的“大幅扩量必须手动受众”“A+一定保下限”“Bid Cap 保证控制实际 CPA”等经验不作为规则。优先读取实际账户设置与官方定义；出价约束和最终获客成本是不同量。
