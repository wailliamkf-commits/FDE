# SEO交付操作：从页面规格到真实回读

按本轮分支阅读：页面生产用1–3，链接调整用4，图片用5，插件迁移用6，表单用7；共同采用8的交付状态。多语言批次另读[多语言变更控制](multilingual-change-control.md)。这些是由视觉材料提炼并补足的FDE操作契约，不是已部署的检查器或视频效果复现。参数由项目确定，案例的篇幅、图像尺寸、分数、发文量与封禁次数不作默认值。

## 1. 输入与PageSpec

输入：业务对象及适用范围、用户决策、目标地区语言、现有URL与模板、查询/页面数据及窗口、可核实来源、允许修改字段、预览/发布通道、资源上限、回退版本。缺少站内数据仍可完成草案，但相应诊断标UNKNOWN。

1. 按用户问题聚类，分清信息、比较、选择、交易/询盘任务；相同词由多个页面承接时先比较意图与分工。确定补现有页、新建、保留分工或提交合并候选。
2. 为每个页面赋予稳定page_id，填写[SEO页面规格](../assets/seo-page-spec.md)：层级/父页、URL、页面类型、主要意图、关键词簇、H1/H2、Title/Meta、差异价值、事实/图片/内链、CTA、优先级、审计状态。
3. 冻结输入文件清单、对象版本与摘要input_digest；登记选择该页面的证据和竞争解释。每个模块写清它解决的问题、claim_id、来源或素材缺口、移动呈现、下一步。
4. 用现有模板制作一个代表页，审核事实、结构、实际交互，再按同一契约扩展相似页。slug同义且没有独立价值时合并规格；关键事实不足时保留草案或降级模块。

输出：PageSpec、事实缺口、明确的页面分工与模块顺序。验收：用户能解释获得什么、适用与限制、为什么相信、成本/时间、下一步；每项关键声明有证据或明确未知。没有现成CMS字段就先填表并人工映射；此表不授予建页/发布权限。

## 2. 内容类型与模块选择

六类是写作路由，不是六种必须建页的搜索引擎分类。共同骨架为直接答复→判断条件→证据/示例→局限→下一步；按任务调整顺序。混合意图选择一个主类型，记录副类型及保留理由。

| 类型 | 输入与推荐步骤 | 输出及验收重点 |
|---|---|---|
| Question | 明确一个问题与适用人群；先短答，再解释原因、条件、例外和例子 | 回答能独立理解；限定条件与结论相邻，附相关深读/行动 |
| How-to | 准备项、权限/工具、起点与成功状态；写有顺序的步骤、步骤结果和失败恢复 | 读者可执行；危险或不可逆步骤有边界，未实测步骤明确标记 |
| Alternatives | 明确原方案哪里不适合；统一筛选维度，对候选逐一写适用/不适用与迁移代价 | 比较同一用途和条件；不凭赞助关系或未核实功能排名 |
| Roundup | 定义候选池、纳入/排除规则与资料日期；按场景分组并说明选择理由 | 覆盖口径透明，能选而非堆名单；没有使用证据不写亲测 |
| Vs | 明确共同任务，逐项对齐能力、费用单位、限制与证据版本；分别给适用结论 | 对比公平，未知留空；不把不同套餐/测试环境当等价 |
| Single Review | 区分公开资料与真实使用；说明对象版本、评估方法、结果、缺点、适用人群 | 没有实际测试则是资料评述；结论能回到来源或测试记录 |

模型/工具目录页可参考下列16块，仅在该业务适用时启用。先核对能力和数据；每块决定KEEP / OMIT / NEEDS_DATA及理由，不靠空表填满模块数。

| 模块 | 纳入前必须具备 |
|---|---|
| Overview | 稳定实体、开发者/供应方、用途与版本证据 |
| Playground | 可用且获准的交互入口、额度/失败反馈；没有实用入口就省略 |
| Image Examples | 合法素材与生成条件，区分演示与真实产出 |
| Text-to-Image | 对象确有该能力，输入/输出及限制 |
| Image Editing | 可接受输入、编辑范围与示例条件 |
| Character Consistency | 可复现对照及限制，不把单图当一致性证明 |
| Product Photography | 适用商品场景，概念/实拍标识与身份保真边界 |
| Text Rendering | 原提示与可检查的文字结果、语言范围 |
| Supported Sizes | 当前尺寸/比例及端点或套餐差异 |
| Generation Speed | 测试时间、负载、参数、样本与分布；文档值另列 |
| Price per Image | 币种、计费单位、参数、地区/套餐及核验日期 |
| Prompt Examples | 有用途的输入和对应输出，保留必要参数 |
| Benchmarks | 数据集、版本、方法、样本与限制；无证据就省略 |
| Compare | 同一场景和口径、各对象证据与未知 |
| API/How to Use | 当前可用接入方式及最小步骤，不暴露密钥 |
| FAQ | 用户实际疑问与有来源的回答；不承诺富结果 |

输出：选用模板、模块取舍表、页面初稿。验收：与PageSpec主意图一致，核心差异有事实支撑；维度不足时只保留有用且有证据的模块，必要时只做说明页而不开放交互。

## 3. 事实审稿与小补丁

输入：冻结稿件、PageSpec、事实资料、引用、适用政策/术语。把内容来源分为OBSERVED（资料中可见）、AUTHOR_CLAIM（作者解释）、FDE_METHOD（本方法设计）、PROJECT_VERIFIED（本项目实测）。来源可追溯不等于主张已证实。

这些标签描述来源种类，另保留工具箱统一的 evidence_status：历史画面报告及作者转述为REPORTED，尚未实测的工程推导为HYPOTHESIS，当前直接可核对的资料或项目测试才可为OBSERVED（注明核验范围）；缺失为UNKNOWN，练习为SYNTHETIC。不能仅因读到旧报告就把其中的上线/效果升级为OBSERVED。

1. 将技术参数、价格、比较结论、效果和资历拆为claim_id；每条指向evidence_id、原文定位、来源版本/摘要、适用对象/地区/方法条件、核验日期。冲突并列，不取平均“消解”。
2. 审稿问题用finding_id，并记录严重性、原文证据、原因、修法、示例和验证方法。自然化改写后再次核查数值、品牌、单位、条件及链接。
3. 提议最小补丁：patch_id、finding_id、page_id、字段/模块/句位、唯一定位锚、before/after、claim_ids、evidence_ids、input_digest、目标对象前置版本、需要的复核。
4. 应用前重读目标。摘要/版本或原文不匹配、定位命中不唯一、补丁重叠时，记STALE/CONFLICT并重建该项。模型提出补丁不等于授权；采用项目已有可信批准或复核记录，不能由Agent自填“approved”创造权限。
5. 获准的本地修改只作用于允许字段；用完整差异检查未登记改动。终稿关联基线摘要、实际应用patch_ids和最终摘要，再复核语义与页面呈现。

输出：声明台账、问题单、补丁表、终稿差异/摘要与复核回执。验收：每项修改都有来源与定位，缺证据的效果承诺撤下或保留待核；输入改变会使受影响结论与回执过期。摘要只证明内容一致性，不证明事实、身份或授权。

没有补丁执行器就人工逐项应用并二次读回；没有核实资料就保留不确定性，不能生成假来源。不得声称本技能已实现哈希链发布网关。

## 4. 内链、冲突页与URL变更

输入：现有URL表、查询×页面数据和窗口、内容/链接图、状态码、canonical/indexability、建页日期、必要的流量/反链证据。

1. 产生候选表：来源页、目标页、上下文、建议锚文、关系、预期解决的问题、证据与置信边界。先补有解释价值的双向路径，链接数量和锚文比例不作通用门槛。
2. 对一词多页比较主意图、模板、用户阶段和真实表现，选择保留分工、差异化、补链或合并候选。流量低、页面新、资料缺失或正文相似都不能单独推出删页/301。
3. 将内链内容补丁与redirect/canonical/noindex/delete分开登记。URL变更须列精确源、真实目标、保留内容、当前响应、批准范围、回退规则及受影响内链/地图；页龄或目标状态未知时先补证据。
4. 执行器获准变更后，读取实际规则与匿名HTTP完整跳转链，确认状态码、Location、最终页内容/canonical、内链和地图；回滚也要重新验真实响应。`DELETE`、空串或占位数字都不是有效目的URL或通用撤销指令。

输出：内链候选、URL变更提案、应用与回退回执。验收：目标可达且语义匹配，无意外链/循环，改动与授权范围一致。401先处理授权、405先核对端点方法；不升级权限或切换写通道绕过限制。没有写权限时交付精确补丁与人工步骤；只完成建议就标PROPOSED。

## 5. 图片：处理、上传、绑定、实际请求

输入：源图清单及摘要、权利/来源、页面槽位、显示尺寸/比例/DPR、允许格式、体积与视觉质量预算、alt语义、平台/CDN能力、现有资源回退映射。

1. **盘点与方向**：按真实文件类型识别图片，非图片单列。记录原尺寸、方向、色彩、透明度/动画。先依据EXIF方向校正实际像素，再移除或重置方向字段，避免双重旋转；保留原件。
2. **尺寸与格式**：依据槽位、裁切与实际显示需求选择尺寸和响应式变体；小源图先考虑保留尺寸/换图，放大需明确代价。用代表图比较格式、画质与字节；透明、动图、细字/线稿不能盲用同一设置。
3. **元数据与输出**：检查并移除不应公开的定位、设备或个人信息，保留必要版权与权利记录；颜色配置按显示验证处理。输出到独立目标，记录源→输出摘要、格式/尺寸/体积、处理参数；逐项机器检查并人工看代表裁切/方向，异常单列。
4. **上传回读**：经授权通道上传后，记录媒体ID、真实URL、服务端变体和回读结果。请求超时先查对象是否存在；仅本地文件通过不能登记UPLOADED。失败时先核对权限/类型/大小/端点能力，获准的后台人工上传可作替代。
5. **页面绑定**：按page_id与槽位绑定资源、alt、固有尺寸和响应式候选；装饰图用空alt，有信息的图按上下文写描述。保存重开精确对象，保留旧媒体映射，不删除可能仍被引用的资源。
6. **前台实测**：在正确预览或公开页、约定视口/DPR查看实际请求URL与所选资源（如currentSrc）、HTTP状态、Content-Type、解码尺寸/字节、DOM alt与构图；确认请求内容是图片而不是状态200的HTML。检查移动裁切、方向、布局和必要文字可读性。

输出：图片映射与每阶段回执，使用[SEO发布矩阵](../assets/seo-release-matrix.md)。验收：所要求槽位均能从源图追到实际请求、显示和alt；LOCAL_READY / UPLOADED / BOUND / REQUEST_VERIFIED分别记录。前台错图/404/HTML先回退槽位到旧资源，再查路径、翻译改写和CDN；不靠修改懒加载掩盖请求失败。

## 6. SEO插件迁移：逐项对账

输入：原/新插件实际版本与模块、平台版本、对象清单、设置/元数据/重定向导出、恢复快照、测试环境、允许迁移范围。只有迁移请求才进入此分支；插件的画面演示不构成安装理由。

1. 建字段映射：对象ID/URL×title、description、canonical、robots、结构化数据、sitemap成员、重定向等实际适用字段。记录源值、目标位置、缺值语义、变换规则；不支持的字段显式UNSUPPORTED。
2. 在可恢复环境试迁移代表对象，包含自定义值、空值、不同模板/语言和跳转规则；核对输出所有者，避免多个组件重复输出同一元数据或schema。按目标平台设计确定唯一责任方，不把“安装了几个插件”当成普适正确性规则。
3. 分批迁移后逐行读回：源值、预期目标值、实际目标值、结果及证据。计数按对象和字段分开；每条源记录进入MATCH / APPROVED_TRANSFORM / EXCLUDED / UNRESOLVED之一，排除项需原因与责任人。
4. `undefined`、缺记录、重复输出、重算不收敛保留UNRESOLVED并定位对象、字段与日志。进度100%只说明导入器结束；未能解释的异常不能核销。关键字段异常阻止该批继续切换，先修复或按快照回退。
5. 对数据层全量可比字段对账；对前台选择风险样本覆盖模板、语言、索引例外和全部受改跳转，验证实际title/meta/canonical/robots/schema/sitemap/HTTP，记录未覆盖部分。旧组件停用与恢复流程先验证；卸载或删数据需要精确授权。
6. 若任务包含分析连接，单列认证状态、所选站点、拉取窗口与新鲜读回；未选站点/未获数据不能借迁移成功宣布分析可用。

输出：映射表、逐行对账、异常队列、运行抽检和切换/回退记录。验收：范围内记录都有去向，关键UNRESOLVED为零，批准变换可解释，前台与后台一致；只验证样本时明示样本边界。无法导出/读取关键字段时缩小批次人工对照；仍无法核实时保留旧稳定方案并交付未决清单。

## 7. 表单、垃圾治理与真实收件

输入：表单字段与成功定义、落库/通知路径、允许的测试收件人、测试授权、现有防护/限额/日志与隐私期限。使用合成测试内容与唯一test_id，不混入真实客户分析。

1. 定义三类用例：正向有效提交；负向缺必填/格式错误/重复/蜜罐等预期拒绝；误杀探针如合法语言、长名称、常见邮箱、共享网络/快速修订。先记录再调整新增封禁规则，不复制案例黑名单或次数。
2. 经授权测试正向链：浏览器提交→服务端接收/记录ID→队列/发送结果→指定真实收件箱收到同一test_id。前端成功、入库、邮件服务“accepted”和收件箱实际收到分开写；如有CRM，再核对映射与去重。
3. 验证负向拒绝理由、保留输入与可恢复提示；确认未误发通知、未制造无效有效线索。测试错误、超时与重试避免重复记录，跟踪事件只在约定成功层触发。
4. 运行误杀探针，复核被拒日志与允许样本；按权限保留最少信息。封禁一旦挡住有效用户，回退新增规则或转观察模式，并提供实际可用的恢复入口。
5. 邮件额度或服务失效时，只有已验证落库且负责人能读到的路径才可作为降级；提示准确说明收到/通知延迟状态，设待发送与人工处理队列。未落库或收件未证实就不能报全链路通过。

输出：三类用例结果、接收/落库/通知/收件箱证据、误杀与失败队列。验收：正向达到约定终点，负向按规则拒绝，误杀测试可正常完成；测试通过不估计真实垃圾率或业务询盘率。没有发信授权时继续本地验证与测试设计，将真实送达记NOT_TESTED；不能擅自联系客户。
