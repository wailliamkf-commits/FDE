# 前沿思考，按需执行：与模型代际解耦

这是调度方法，不是已经运行的模型路由器，不修改账户默认模型、订阅、API配置或安装服务。角色名不是API模型ID。宿主实际工具、权限和数据政策优先于本文。

## 1. 开工能力发现与选择

建立本轮模型能力快照：核验时间、宿主/供应方、实际可选模型ID、工具/视觉/上下文能力、支持的推理档位、使用上限、数据边界、当前成本或UNKNOWN、来源。先查宿主能力清单，再查供应方当前官方文档；公开发布不等于当前账户可调用。不同平台的同名选项不保证同价或同能力。

思考模型选当前已获授权、实际可用且适合复杂判断的前沿模型。不能靠名称数字最大或发布时间最近判定最优；需官方定位、能力匹配和小样本任务证据。用户指定供应方/模型时不擅自跨供应方；前沿模型不可用则标BLOCKED_MODEL或请用户批准替代，禁止静默降级后仍称前沿。当前模型如不能自切换，只能调用宿主支持的委派/切换入口或交出工作单，不能用“现在我是X”提示词假装换了模型。

由思考模型生成结构化决策摘要（结论、依据、取舍、验收），不要求公开内部思维链。任务执行前锁定本批次模型与档位；读取能力/官方文档不自动启动计费试跑。只有已获准的预算和调用范围内才做小样本评测。

## 2. 三种角色及最低合理能力

| 角色 | 责任 | 何时结束/交接 |
|---|---|---|
| Frontier planner | 业务模式、关键架构、风险判断、冻结范围、选择执行模型、关键故障根因、最终Gate | 有一个可行主方案与可测试工作包就停止设计，不等待理论最优 |
| Executor | 依照契约编码、内容模块实施、调试、测试与发布准备；通常选中等能力模型，也可因实证选择更轻或更强模型 | 返回实际变更、测试证据和异常，不自行扩大范围 |
| Routine worker | 已确定的提取、分类、格式转换、可重复批处理 | 在确定规则与校验下完成；歧义移交，不猜测业务事实 |

独立复核是一个职责，不一定需要最高模型或新常驻代理；重要发布由思考角色依据足够证据做最终Gate。视觉/代码/浏览器工具能力是硬约束，不能只比token价格。思考模型可保留关键决策，普通工作批量交给执行者；若宿主不支持多模型委派，则记录“单模型执行，路由未实现”，不承诺已节省额度。

执行选择顺序：满足工具与数据硬条件→满足任务质量下限→比较总交付成本（调用+上下文交接+延迟+重试+人工复核）→选择最低合理层级。中等模型是默认执行候选，不是必须使用某代某名；不用低能力模型连续试错，也不把所有普通操作交给最高模型。

推理强度与模型分开选择，只用宿主支持值。复杂关键判断才提高强度；不把Ultra/Max或“最贵”当全程要求。未知价格不编造节省百分比；记录调用次数、观察到的用量/时长、重试数、验收结果作为后续比较。

## 3. 可执行工作包

使用[工作单](../assets/model-work-order.md)，只传目标、选定方案、必要上下文/文件指针、输入真实性、允许的对象/动作、保留项、接口、预算、验收、停止/升级条件。不要把完整历史、账号凭据和客户数据广播给每个代理。禁止两个写入者同时编辑同一主题文件、同一个后台表单或共享浏览器焦点；并行限于可独立验证的不同写入范围，集成发布由单一写入者完成。

执行者先验证输入和目标，连续完成一个工作包，再集中测试。第一次同类失败依据日志/页面/回读结果修复；第二次停止补丁并回到思考角色定位根因。只有新证据证明新方案可行才允许下一次执行，不把无权限/真人验证/API限流视为能力问题无限换模型。

最终Gate核查原目标、硬要求、无关改动、回归、安全/数据/稳定性与测试证据。结果PASS或FAIL+必须修复项；OPTIONAL不阻止已达标批次。执行模型不能自行把失败测试改成更宽标准。

## 4. 面向下一代模型的升级

每个新版本批次启动、当前模型退役/不可用、能力/价格/上下文发生实质变化或同类失败达到升级条件时，重新核验；同一批次小改动复用已锁定结果，不每次重搜排行榜。新模型先跑固定的合成代表任务与回归检查，比较正确性、证据质量、耗时、成本和工具兼容，再由思考角色建议升级。跨供应方/付费方案变化仍需相应批准。

保留“请求选择”和“实际返回模型/档位”两列；执行记录如无法确认有效模型则写UNKNOWN，不能只抄请求值。已开始的发布批次不在一半无证据换模型；升级失败回到上一个获准配置而不是复制整个项目多套备份。

结果分三层：ROUTING_PLAN_ONLY（方法/工作单）、ROUTE_VERIFIED（实际宿主选项与执行回执）、DELIVERY_VERIFIED（业务目标与测试通过）。本技能文件只提供第一层方法；安装成功不自动获得后两层。
