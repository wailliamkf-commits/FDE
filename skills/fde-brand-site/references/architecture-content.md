# 页面架构与内容系统

## 1. 先建信息模型，再做页面

先按业务模式定义供给对象（商品/服务/方案/内容）、选择条件、证据、交易或请求、履约/访问状态。字段必须服务用户选择与后台兑现；不适用字段标NOT_APPLICABLE，缺失字段标UNKNOWN，不能转换成0元/有货。

零售/定制分支再区分设计家族、具体模板、真实库存单元、配置/报价版本、订单/服务。证书是具体对象的证据字段，不是共用的装饰标签。其他模式按适配表使用时段/预约、方案/权限、规格/询价等对象，不生造SKU。

分类按用户选择任务：类型、用途、风格、材质、形状/尺寸、预算、可定制范围等。只给有可靠数据且能改变选择的筛选；缺值显示未知或不参与该筛选。家族用稳定分类ID；唯一库存用唯一SKU；组合配置避免把所有排列乘成SKU。售出库存保留准确状态和替代路径，不能继续显示InStock。

零售路径：发现→筛选→具体可售商品→选项→价格/税运→结账。定制路径：设计与证据→可修改范围→需求→报价→确认→制作。服务路径：适用/覆盖→人员与流程→时段→请求→确认；订阅路径：用例→方案→注册→激活→使用/取消。混用时明确动作的真实含义，不放无效购物车或预约按钮伪装完整。

## 2. 逐页职责与模块（按业务适配，不是全套强制安装）

| 页面 | 核心问题 | 常用模块顺序 | 下一站/边界 |
|---|---|---|---|
| 首页 | 这是谁、适合我吗、值得继续看吗 | 品牌场景+价值主张+主/次动作→事实型信任短条→分类发现→代表设计→用途/人物情境→方法或真实过程→品牌观点→精选指南→FAQ/下一步 | 先品牌后选择，长询盘表单通常不占首屏；没有依据就不放销量/媒体logo |
| 系列/列表 | 哪一类更适合我 | 类别说明/视觉→筛选排序或家族导航→卡片→比较或选择帮助→关联系列 | 卡片标清名称、关键差异、状态与价格范围；无结果有清除筛选/咨询出口 |
| 商品/设计详情 | 我到底获得什么、能改什么、如何继续 | 身份图/侧面/比例/场景图库→摘要/状态→选项与总价或报价边界→行动→规格/可修改范围→制作和交付→售后→相关方向 | 概念图不代表实物/库存；重要费用、交期、退改限制不能藏在最底部 |
| 库存选择 | 哪个单元对应我的要求 | 数据新鲜度→参数筛选→唯一SKU/报告/实图→比较→保留/下一步 | 双人同时选择、售出、失效、证书不匹配均有明确状态 |
| 定制服务 | 从模糊想法到方案需要什么 | 服务区别→可做/不可承诺→起点示例→输入/输出流程→时长/费用规则→简短需求表→确认回执 | 原创与模板修改分流，提交不是订单，不自动承诺可制造 |
| About/Story | 为什么存在、观点如何体现在产品里 | 核心观点→人物/环境→真实起源或当代方法→设计原则→产品/服务对应→继续浏览 | 不需要杜撰传承；故事每段应有具体产品或服务映射 |
| Process | 下一步会发生什么 | 阶段、顾客输入、品牌输出、确认关口、计时起点、异常分支 | 设计确认/生产/运输分开；业务给定20天不推广为通用行业承诺 |
| Guides/材料/尺码/护理 | 如何降低选错和售后风险 | 问题导航→图表/操作示例→适用与限制→相关设计/服务→求助 | 尺码和工程知识需来源，示意不变成安全保证 |
| Journal/博客 | 一个具体问题怎样决定 | 导语直接回答→比较/解释→证据/图示→局限→下一步链接→真实署名/来源/修改日期 | 每篇只承接一个主要意图，不为字数填充 |
| 政策与联系 | 我承担什么、出了问题找谁 | 易读摘要→完整真实政策→费用/时间/例外→联系及其他政策 | 摘要与正文一致；隐私/经营信息法定义务单独审查，不用空白身份作为通用策略 |
| 系统状态 | 找不到/失败/取消了怎么办 | 404、空列表、搜索无结果、表单错误、成功状态、失效配置 | 给解释、保留输入、返回路径；不以成功动画代替真实提交确认 |

## 3. 模块契约和连接

每个模块定义：入口意图、一个主要问题、标题/短答、所需事实、视觉角色、主要动作、目标URL/传递字段、错误/空状态、移动展示、验收。按“情绪识别→理性比较→信任→行动”安排节奏，但允许高意图搜索直接进入详情。

跨页链接靠语义而非“了解更多”泛用词：材料指南回到相关配置，博客比较回到设计类目，设计带入可编辑需求摘要，服务页回到当前决定。保留返回、清除、修订路径；详情不能成为死胡同。页脚是次级导航，不负责承载全部主旅程。

## 4. 内容编辑与完整度

事实→选择影响→有边界的收益→证据。把重复免责声明集中为清晰状态标签和展开解释，关键费用/交期/权利保留在行动旁。删除无新信息的抽象形容词；用对比、尺寸示意、步骤、状态和图注代替整屏段落。

建立声明台账：文本/字段、来源、适用对象/地区、核验日期、负责人、到期条件、允许页面。真实性不足则降级为设计意向、草稿或待确认，不以生成图、星级、图标弥补。

“完整”不是全模块装齐：顾客可回答是谁、获得什么、适用与差异、为什么相信、代价/时间/风险、如何继续、如何求助。每项标VERIFIED/NEEDS_DATA/NOT_APPLICABLE并给证据；有页面但无法回答，不算完成。
