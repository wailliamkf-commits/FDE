# 实验、预算与因果

## 最小实验契约

使用 `../assets/experiment.json`。启动前固定成本分母（零投放对照的相关费用，或非零基线扩量的增量费用）、规模校正规则、需求单元、主要假设、竞争解释、实验变量、对照/分配单位、主指标、护栏、最小有意义变化、预算/时间上限、购买/退款成熟窗口、排除规则、复盘日期、责任人、停止/回滚条件。

优先随机对照；无法随机时可用匹配地区、分批上线、时间序列等较弱设计，但说明季节性、组合和同期活动混杂。样本不足写“不确定”，不把“没有统计显著差异”写成“没有效果”。不要每日偷看后任意提前宣告胜出；异常安全/成本护栏可立即终止。多变量同时变化只能评估组合，不能归功给其中一个。

## 决策矩阵

| 情况 | 决策 |
|---|---|
| 追踪/目标/归因混乱 | 修复并对账；只冻结依赖问题数据的扩量 |
| 成熟结果达到业务约束且增量可信 | SCALE_CANDIDATE，分阶段扩大并观察边际、库存和现金 |
| 上游改善但商业结果未成熟 | TEST，等待完整周期；不把加购价值当收入 |
| 成熟贡献差且替代解释已检查 | HOLD/收缩/替换，优先保留内部有效商品 |
| 数据少或实验污染 | NEEDS_DATA/重设测试；不宣布输赢 |

常规预算10%或20%的调整是项目操作习惯，不是算法的普适硬门槛。大预算成熟失败可以更快停止，小预算测试要足够获得信息；具体金额来自风险承受与样本设计。历史投入是沉没成本，不构成必须继续花费的理由。

## 典型实验

1. **同意图集合页对商品页。** 相同市场和人群、可比商品/价格；以成熟购买/贡献为主，商品推进和加购为辅。高跳出只是诊断信号。
2. **查询/Feed拆分。** 将供电、安装、使用场景或功能不同的商品与意图匹配；观察单位商品贡献和量。避免同时重定价、换素材、改全部预算。
3. **需求开发。** 分开冷人群与再触达，分别检查受众、商品、素材和优化事件。再触达更高归因回报不证明新增需求增加。
4. **品牌捕获。** 区分品牌核心、品牌+品类、评价、优惠和非品牌。品牌搜索回报高可能承接已有需求，增投需要机会与增量证据。
5. **新市场/伙伴/自然渠道。** 用最小可交付承诺获得真实购买/报价证据；评估全成本和周期，不因无需点击付费就免费无限试。

## 零售与B2B

零售：订单、取消、退款、履约和贡献沿首次获取队列观察。
B2B：有效线索、合格商机、报价、合同、回款分别记录；预计管道价值和已实现收入分开，赢单概率由历史队列校准。一个高赋值表单不构成扩量证明。

## 经营压力测试

将渠道流量减少、获客成本上升、主力商品缺货、交期延长设为明确情境（幅度由业务选定，并非预测）。估算现金/贡献/服务影响和恢复时间，记录替代渠道/商品的可执行容量。只看渠道数多不能证明有韧性。

归因分配功劳；增量实验评估相对对照多产生的结果。官方参考见 [sources.md](sources.md)。
