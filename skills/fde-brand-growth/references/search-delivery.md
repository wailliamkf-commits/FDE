# SEO / GEO：从知识点到一轮网站交付

用于自然搜索机会排序、页面工作包、询盘增长或视频经验落地。配套 [机会工作表](../assets/search-opportunity-workbook.md) 与 [指标记分卡](../assets/search-scorecard.md)。这是可按项目选择的方法，不是自动采集、发布、投放服务。

## 1. 最少输入与进入条件

确定一个需求单元：网站/平台、业务模式、目标市场语言、采购者与购买周期、产品事实负责人、目标动作、现有URL、获授权环境、预算/工时和验收人。未知项目留空并列补数，不要求先搭大型数据平台。

建立四张互不混写的输入表：

| 表 | 最小字段 | 用途 / 缺失备用路线 |
|---|---|---|
| 查询与意图 | query、来源、国家库、语言、设备、窗口、抓取时间、估计/实际/模拟、指标单位、意图簇、现有URL | 缺付费工具用授权GSC导出和小样本人工SERP；不能把缺搜索量补0 |
| 页面库存 | URL、模板、语言、主意图、父页、HTTP、indexability、canonical、内链入口、当前版本 | 缺抓取器先用CMS导出加人工重点页；注明覆盖，不声称全站审计 |
| 事实与资料 | claim_id、规格/单位/适用条件、来源版本、负责人、权利、失效时间 | 缺证据暂停该主张，可继续版式草稿；模型不补参数/认证 |
| 业务队列 | 脱敏线索ID、到达时间、来源可信度、去重、资格、处理/报价/成交时间、金额和成本口径 | 缺CRM用受控人工台账；只记录必要字段，原件留客户项目 |

如输入来自历史视频或二手报告，先在基础包 `fde-case-delivery-foundation` 的 `source-coverage.json` 按 new-video-ID 查询技术细节及限制。原视频中看见工具，不等于本机已经连接；没有该参考包时可以继续此流程，但来源检索标不可用，不能编造其内容。

## 2. 机会判断：先判任务，后看数值

1. 从销售/客服问题、真实查询、产品限制、竞品承接缺口提出需求。按采购阶段细分，不硬套“大企业一定关心认证”。
2. 读取现有页及相同市场的SERP，区别信息、比较、选型、交易、导航；记录观察样本、时间、页型和不确定性。第三方KD、SV、DR只在同工具/库/版本内作参考；不设置通用“KD小于20必做”。
3. 先匹配现有内容：保留 / 补事实 / 分工互链 / 新建 / 待合并核查。一个查询出现多个URL只是调查入口；商详与选型指南可承担不同任务。
4. 优先级采用分层排序：已证实阻断真实客户或安全问题 → 证据充分且可低成本验证的商业缺口 → 探索。每项写商业价值假设、证据把握、工作量区间、等待依赖、风险、可逆性。数量打分如有使用，须注明团队自定权重并做敏感性比较，不包装为Google评分或直接自动发布。
5. 选择一个能改变决策的小批次；范围大小按模板/语言/风险分层，包含正常、缺数据、失败路径。先通过代表性页面再扩同类，而非按固定篇数交付。

输出：有证据链接的排序表、保留/不做理由、PageSpec清单和本轮唯一主假设。没有可服务需求或独特资料时，备用是改进已有入口与销售问答，不批量填充AI文章。

## 3. 可交给另一位执行者的工作包

每个工作项绑定 `demand_id → cluster_id → page_id → claim_id → change_id → acceptance_id`。交接内容是具体对象、版本和产物，不是“优化SEO”。

- **意图工作包**：查询导出、语义簇、SERP依据、现有页职责、排除词理由；产物是关键词到页映射。验收为范围内每个候选有去向/待定原因，而非所有词都有新URL。
- **页面工作包**：目标人群、问题、业务事实、页型、父子关系、主标题/分节、证据、图表、CTA、双向内链、语言、索引意图；执行者可使用现有 fde-brand-site。缺事实的字段写UNKNOWN，不能把采购规格猜成文案。
- **内容工作包**：从 Question / How-to / Alternatives / Roundup / Vs / Single Review 中按任务选；比对事实、反证、来源、限制及读者下一步。人工/AI自然化后复核数字、单位、否定词、型号、链接，不只检查流畅度和字数。
- **技术工作包**：把“候选异常”变成准确URL/字段/前置状态/期望状态、影响入口、回退。跳转、删除、noindex、Disavow需另行精确授权；保留页面、差异化及补内链是更低破坏性的可选路线。
- **测量工作包**：按 [搜索指标契约](search-measurement.md) 冻结来源、分母、观察窗口、成熟度、质量/运行/业务三层验收。没有身份关联只作事件对照，不作漏斗。

以上模板不授予生产权限。增长负责人决定为什么做和投入多少，站点负责人负责改什么及保存/前台回读，销售负责人确认有效线索和业务反馈。同一项事实只维护一个项目台账。

## 4. 主方案、备用方案与停止条件

| 场景 | 主方案 | 备用 / 人工兜底 | 切换条件与再进入 |
|---|---|---|---|
| 授权取数可用 | 只读导出GSC、分析系统及去重业务队列 | 版本化手动CSV+重点页人工检查 | API失败或覆盖不足切备用；补数对账后回主线，不换服务商偷传资料 |
| 内容事实充分 | 小批次证据驱动草稿、审稿后申请发布 | 内部FAQ/采访提纲，暂不上线未证实主张 | 参数/权利/承诺冲突转HOLD；负责人确认后重做受影响下游 |
| 页面职责不清 | Query×Page×意图分析并观察分工 | 保留URL，改导航/内链/解释 | 有明确重复价值和保留目标才形成合并方案；无授权不执行 |
| 数据量低 | 描述基线+用户理解/可用性验证 | 延长约定观察或补访谈 | 未达预设样本/成熟门槛标NEEDS_DATA，不用短周期宣判业务失败 |
| AI问答波动大 | 固定问题集、版本、重复采样及引用核对 | 人工少量核对+真实referral/自述来源分列 | 服务/版本/联网状态变了重建比较基线，不拼成同比 |
| 发布后链路异常 | 停当前批次，按冻结变更集回退并回读 | 已核验的旧版或人工接收线索 | 404/错误跳转/邮件未到/事实错公开时先处理用户损害；恢复证据后再扩量 |

停止本轮的条件是预定产物与证据完成、达到资源上限、出现新授权边界或反证推翻假设；持续输出不是产出。下一轮由证据触发，不是“执行器空闲就再写文章”。

## 5. 不把采集知识当作已实施架构

Agent仅需要有边界的任务状态、输入版本、工具契约、证据、错误和下一步。调用权限来自宿主与服务，不来自提示词或自写批准JSON。单一派发者、读写分离、一次请求状态核对、断点恢复比无界多Agent更重要。

已有Harness可以作为受控执行者；没有Harness就由当前GPT/人工按工作包交付，不为了SEO新建常驻平台。知识采信需要问题集与反例测试；原报告、转述和再次汇总属于同一证据族，不增加独立证据数。源码/模型/安装和真实运行记录不足时只交架构建议。
