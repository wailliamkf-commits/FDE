# 付费媒体诊断：Google Ads 与 Meta

本模块把已提供的两份本地内容包接入 FDE 的「增长与经营 → 付费媒体」。当前工具箱版本为 0.1.12；技能内容版本分别为 Google 2.2.0、Meta 1.1.0。两者都交付诊断与可审阅任务，不是自动投放服务。

## 选一个入口

| 要解决的问题 | 技能入口 | 随附内容 |
|---|---|---|
| 搜索意图、商品广告、购买目标口径、实际 URL 与页面承接 | [Google Ads](../../skills/google-ads-diagnostics/SKILL.md) | 16 类数据入口、12 类问题、8 份参考资料、4 张空白任务表及5个历史复核合成情境 |
| Meta 素材承诺、平台/版位、目录多 URL、网站或原生表单质量 | [Meta Ads](../../skills/meta-ads-diagnostics/SKILL.md) | 14 类数据入口、16 条指标规则、17 类问题、3 份参考资料、1 张整改任务表 |
| 跨渠道阶段、需求验证、资源与增长约束 | [品牌增长](../../skills/fde-brand-growth/SKILL.md) | 统筹决策；需要渠道细节时再选择专项 |

沿用仓库平铺的 `skills/<name>/`，不新建一套分层安装机制。两项广告技能的内部引用均在各自目录内；可单独接收完整技能目录。目录分类是检索元数据，不是宿主权限配置。

新增 [账户架构与探索补充](ARCHITECTURE_UPDATE_20260928.md)，包括当前平台机制及本轮情境验证。

## 如何使用

在可读取仓库文件的工作环境中，先按仓库接收规范固定提交，再读取对应 SKILL.md。提供已有导出、素材、页面及目标，技能会按问题补最少的数据；没有账户连接时也可以用文件开展分析。此路径不要求额外插件或个人账户原生安装。

可用请求示例：

- 「使用 google-ads-diagnostics，核对这两期购买 ROAS 的口径，再给我取数入口与具体页面任务。资料不足处不要猜测。」
- 「使用 meta-ads-diagnostics，关联素材与实际到达页，区分流量、内容、操作和测量问题，列出证据与整改验收。」

原生发现与调用取决于实际宿主；只有明确需要安装时，才按 [可选安装说明](../INSTALL_AND_WORK.md) 使用现有项目级安装器选择 `google-ads-diagnostics` 或 `meta-ads-diagnostics`。不安装全局目录、不新增广告连接、不扩大现有权限。

## 来源与迁移

[source-map.json](source-map.json) 保存上游整包哈希、原路径、接收路径、原文件哈希和有限编辑说明。Google入口的本地附加段另存版本与哈希；验证时剥离该段和版本元数据，继续核对原上游字节哈希。Google 上游建议路径 `skills/growth-marketing/google-ads-diagnostics/` 在整合时改为现有平铺结构；整项移动不改变相对引用。

本次材料是上游对话形成的知识提炼，不等于取得了最早 Google Ads / Facebook Ads 知识库的全部历史原文与图片。原始客户报表、文章截图、账户明细、完整对话及凭据不进入本仓库。原上传说明中的目录猜测、404 或延期状态不是当前环境事实。

保留以下历史记录供追溯，开头均有 `IMPORTED_HISTORICAL` 标记：

- [Google 原本地验收](imported/google/validation/RESULTS.md)及其两份合成输入，合计四个案例。
- [Meta 原本地验收](imported/meta/docs/VALIDATION.md)与[三个合成案例输出](imported/meta/docs/forward-test.md)。Meta 包未提供独立原始测试输入/运行日志，不把输出重包装为完整可重放试验。

原始“开始阅读/上传交接”文件仍由维护者保存在资料工作区，避免将已经完成的上传指令变成每次技能调用的任务。没有丢弃上游素材；本仓库只收有复用价值的内容。

## 验证层次

1. **包完整性**：核对原 ZIP/JSON 的逐文件哈希；迁移与编辑后重新生成仓库 MANIFEST。
2. **本地整合**：现有标准库回归，加上目录/版本一致性、内部链接、编号、来源漂移检查和临时项目安装检查。安装检查只证明文件可复制且不覆盖，不证明宿主实际发现。
3. **技能行为**：上面的历史合成结果保留上游声明，原导入轮未重新运行独立模型行为评测；本轮增量验证见上述更新记录。结构或关键词检查不能替代行为评测。
4. **真实应用**：Google/Meta/GA4/Shopify 的菜单、权限、字段、账户关联、真实经营改善均需在具体任务中另验。参考资料中的 2026-09-12 是上游文档核验日期，不是本轮账户实测。

本轮实际运行输出、最终 GitHub 提交与 PR/合并状态由包外交接回执记录。仓库文件、原生安装、广告投放与业务效果必须分别报告；本包不授予预算、受众、Feed、网站或消息写入权限。
