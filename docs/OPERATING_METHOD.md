# 从岗位需求到可复用交付

岗位基线见 `FDE_JOB_REQUIREMENTS_BASELINE.md`。用户提供的招聘截图和公开岗位页都是有限样本，不是全面市场统计或付费需求验证。
从中提炼：业务发现、价值与范围、亲手实现、系统集成、质量与采用、生产运行、复用与商业边界。

工作循环：问题与价值 → 当前事实 → 有限任务 → 集成契约 → 实际成果 → 独立验证 → 运行/使用反馈 → 有证据的复用。
每轮保留一页场景卡、一张机器可读任务、成果和结果；涉及外部系统时补集成契约，生产候选补评测/上线记分卡，形成可复制结论时补复用/产品反馈。已有项目可映射原格式，不强迫另建重复文件。

任务负责：唯一 owner、版本化输入、允许的路径/动作/对象、验收、预算、停止/恢复条件。
worker 交 REVIEW；QA 检查后才 VERIFIED。代码存在、远端接受请求、按钮能点，都不能单独证明业务完成。
READ → LOCAL_WRITE → STAGING_WRITE → PRODUCTION_WRITE → HIGH_IMPACT 是风险分类，不是自动升级路线。

自主程度看：授权范围内无需人介入且验收通过的任务比例；另外报告被批准步骤、返工、人工介入、严重错误和采用分母。
成本看：模型/运行资源 + 人工审核返工维护，按合格任务计，不只看 token 单价。

学习：实际任务暴露 API、数据、Git、测试、部署、视觉和产品表达缺口，再定向补齐。
案例记录：为什么做、自己做了什么、AI 协助了什么、失败如何解决、效果和复用证据。不要夸大独立工程经验。

创业：先诊断/试点/有限交付，量出服务成本、采用和跨场景复用，再考虑产品化；不要先建设全行业平台。
本仓库不训练基础模型，不建设万能知识图谱，不创造第二套项目总控。
