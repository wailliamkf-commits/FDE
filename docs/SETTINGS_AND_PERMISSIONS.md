# 设置与操作准备

## 建议的初始设置

连接器：允许获准数据的读取，写入仍询问；授权只包含工具箱仓库和当前项目确需的对象，不选择全部组织和仓库。
本地：从只读开始；实施阶段仅写入已批准项目目录。不要使用 danger-full-access 或关闭审批来解决接口不通。
网络：默认不为本工具箱启用；初次上传只对 GitHub 已认证通道放行。新目的地、第三方服务、模型供应商须另核对。
模型：按实际可用能力和基准任务选择，requested/effective 分开；不把旧聊天模型名直接写为 API ID。
并发：一个有效总控，最多两个 worker；无递归派发；同一对象单写。不是必须创建六个新对话。
预算：模板默认外部费用 0；实际项目另定上限。配置一个数字不代表平台已经执行了限额。
清理：只有预览；不改变用户原来的“不永久删除、不清空废纸篓”边界。

日常运行只需要本工具箱自身的 Skills。GitHub 用于仓库同步；浏览器、邮件、设计、商城、工单或企业系统插件，只在某个已冻结任务确实依赖时连接并采用最小权限。`skill-creator`、`plugin-creator` 是维护工具，不是每个项目的运行前提。

## 配置不是自动生效

configs/*.json 均为本工具箱意图和记录，不是 Codex/Work 原生配置。
不得直接覆盖 config.toml、AGENTS.md 或现有项目批准策略。
在当前宿主查看版本与官方 schema，修改前给出差异、保存原配置，验证生效后再报告已设置。

特别注意：官方 permission profiles 文档仍标记 Beta，且与旧 sandbox_mode 配置存在优先级/兼容规则。
不能把两套设置混在一起就宣称限制已经生效；本包故意不自动安装原生配置。
网络域名清单也必须有实际代理/平台控制执行，写进 JSON 不会自动阻止外联。

## 最小验证

只读环境尝试写一个指定沙箱测试文件，应被宿主阻止（测试需事先授权，不访问真实敏感文件）。
草稿环境测试允许目录与拒绝目录；使用模拟文件，不能拿真实密钥做探针。
连接器做一个获准只读动作；write capability 单独核实，不用创建真实订单验证。
保存结果与时间，不能仅截设置界面就宣布权限已验证。

## 现有项目

沿用原产品事实、发布门禁、队列和总控。工具箱安装不是授权发布。
新对话只负责工具箱接入与一个试点任务，不能暗中与原总控共同写生产。
