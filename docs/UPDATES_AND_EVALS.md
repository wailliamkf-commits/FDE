# 灵活更新，不自动追新

分清两条线：研究区发现新模型、新图像工具和新技能；项目执行使用已批准的固定版本。
GitHub main 是开发入口，不是自动部署通道。任务记录 toolbox commit + manifest digest + skill version + 输入版本。

更新流程：官方变更 → 隔离试验 → 固定样本比较 → 安全与数据流审阅 → 小范围验收 → 批准 → 版本锁定与回退。
模型可用列表来自实际宿主；营销名称、UI 名称与 API ID 不混用。
第二服务商是数据目的地变化，不是纯粹的技术替换；未经授权不得备用外发。

最初评测至少覆盖：正确需求、资料缺失、来源冲突、模型诱导越权、工具不可用、重复请求、超时结果不明、产物与验收不匹配、符号链接/路径越界、活动文件清理。
本包单元测试验证确定性工具边界，不证明模型会正确触发技能。宿主还需正向/反向触发测试、真实输入与人工复核。
首次对自动触发关闭；显式调用稳定后，审阅 agents/openai.yaml 与宿主能力，再决定是否开启按需匹配。

对比指标：任务通过率、严重事实错误、人工修订耗时、成本、延迟、工具成功率和恢复能力。
不同模型投票不等于正确；重要结论依赖独立事实、程序与实际回读。

技能更新可以提出 PR，但执行者不得自行升级当前运行的安全规则、白名单和审批条件。更新评审与使用分开。
安装器目前支持首次复制和完全一致的幂等复用，不支持无审查覆盖升级；已有版本更换需单独迁移计划。

完善顺序：真实宿主端到端测试 → 一个真实业务纵切片 → 精确对象的受控写入适配器 → 实际审批与审计 → 可靠调度/恢复 → 经第二案例证明的行业能力。
先拿一项有基线、有使用者、有验收的成果验证现有工具箱，不先增加几十个 Skill、向量库、多租户平台或新的 Agent 框架。
