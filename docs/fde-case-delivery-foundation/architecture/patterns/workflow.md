# WF：有状态固定工作流

选用：字段明确、步骤和规则稳定。排除：需要动态搜索未知路径时，仅把稳定部分留在本模式。

## 组件与数据流

输入校验 → 规则决策 → 状态机 → 工具适配器 → 结果读回 → 完成或异常队列。LLM 可以抽取自然语言字段，但状态迁移由确定性规则决定。

## 字段与实现

编辑建议字段：task_id、input_version、current_state、allowed_transition、precondition、action_id、result_ref、updated_at。明确区分待处理、已提交、结果未知、已确认、失败；具体枚举按业务定义。
先用脱敏样本写出状态/迁移表，再为每个迁移定义前置条件和结果证据，接入只读或本地模拟工具，最后才评估获授权写入适配器。状态落库不能由模型一句“成功”触发。

来源拒收案例（video-013，130–150 秒）：待确认→拦截中→已拦截→退款中→已退款→库存已释放。其业务规则不直接套用其他平台；每个副作用另有幂等与读回检查。

## 备用、故障与验证

无 API 时使用批准的 CSV/人工操作单，牺牲实时性而非权限。未收到执行回执进入结果未知，先查询后决定补偿；已付款等不可逆动作不声称数据库回滚能撤销。
测试：缺必填字段不执行；重复 action_id 不重复副作用；旧 input_version 拒绝迁移；工具返回空值不标完成；任务中断恢复到最后已确认状态。
