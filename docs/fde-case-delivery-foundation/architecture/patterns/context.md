# CX：上下文预算与信息保全

选用：工具返回/历史占满窗口，或长任务关键约束被挤出。排除：短任务不需要影子总结服务。

## 组件与字段

消息/附件→大小与用途分类→外置资料索引→旧结果裁剪→分段摘要→不变量检查→恢复当前上下文。
编辑建议：artifact_ref、source_hash、summary_version、goals、decisions、constraints、open_questions、last_confirmed_step、evidence_refs、compression_failures。只存显式决定和依据，不要求隐藏推理。

## 实现顺序

先建立压缩前后检查集：业务目标、批准边界、关键数值、失败项必须不丢。大文件留引用；删去重复旧结果而保留必要证据位置；早期探索可以摘要，设计决策和当前步骤保留。完整纪要作为兜底，不把所有内容粗暴搅成摘要。
缓存前缀和服务端编辑依赖供应商实际接口；冻结前缀与改写历史存在取舍，先测再选。记录真实使用量、估计费用与重试开销，不能只比单次 token。

备用：生成交接摘要并停止/另开经批准会话恢复。压缩失败次数由项目定上限，失败后保留原记录，不无限后台重试。
测试：压缩后仍正确引用金额/单位/权限；产物路径可读；失败动作不变已完成；摘要证据缺失返回未知；预算不足明确中断。
