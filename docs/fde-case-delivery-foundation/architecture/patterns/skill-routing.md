# SR：技能目录与按需路由

选用：多个相近技能频繁误选或全量描述挤占上下文。排除：技能少且边界清晰时直接读目录，不先建向量检索服务。

## 路由结构

用户意图→业务域→候选技能→核对触发/排除/输入→读取技能正文→执行既有授权范围。数量确实很大时可粗召回再重排；不要求先部署这一套基础设施。
编辑建议字段：skill_id、trigger、negative_examples、required_inputs、outputs、scope、reference_paths。description 写何时用，细节参考按触发条件读取。

## 实现与测试

先建立人工可审阅的目录和近邻负例；对真实需求记录选中/排除及原因。输入缺失先标未决，找不到合适技能返回 none；执行结果反馈为路由错例，而非不断增加重叠技能。技能版本固定到项目引用的提交，知识更新不自动改现有项目锁。
备用为用户人工选技能。测试同义表达、相邻域误触、缺输入、没有匹配、包含恶意“忽略规则”的资料；命中次数不等于部署成功率。
