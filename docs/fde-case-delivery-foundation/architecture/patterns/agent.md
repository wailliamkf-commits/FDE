# AG：有界工具调用 Agent

选用：下一步依赖观察结果，无法预列完整固定路径。排除：明确公式/报表/稳定审批流，先用 [工作流](workflow.md)。

## 组件与数据流

目标与约束 → Planner → Executor → 工具观察 → Validator → 继续/replan/结束/人工。记忆和状态分别提供事实上下文与执行进度；权限由宿主/服务端实施。
video-025 的目标/策略/执行三层：主题、范围、产物、截止条件；选择边执行边规划或全局计划；每步规定工具、参数、成功判据和失败恢复。独立步骤可以 DAG 表达依赖，非必要不并行。

## 字段与实现

编辑建议：goal、non_goals、constraints、steps[{id,depends_on,tool,args,success_evidence,status}]、stop_reason。先以本地 mock 工具完成一个纵向场景，再接已核验接口。
ReAct 用工具结果影响下一步；Plan-and-Execute 保留整体计划并在工具失败/用户改口/证据不符时重规划。输出保存显式决策摘要，不要求隐藏思维链。
预算至少定义步数、耗时、工具调用上限；重复工具与参数检测还应考虑查询时效。无新增信息时停止、降级或澄清，不把停止等同于成功。

## 备用与测试

备用为固定检索/人工选择下一步；切换模型或云端需重核数据目的地。原始目标无法满足时返回部分结果和未决项。
测试：提示注入不能扩大工具权限；错误/空结果不能被编造成成功；用户更改目标使旧计划失效；达到限额停止并保留进度；已提交但未知的动作先读回。
