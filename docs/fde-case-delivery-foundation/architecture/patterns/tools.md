# TC：工具契约与受控副作用

选用：Agent/工作流访问外部系统。排除：单纯写方案时不实际开接口或申请全盘权限。

## 三层链路

请求→输入 Schema/业务前置条件→真实权限与批准检查→调用→结果结构/业务校验→状态读回和审计。模型给出调用建议，执行通道负责强制约束；技能文本不是安全网关。

## 字段与实现

编辑建议注册项：name、use_when、avoid_when、input_schema、output_schema、risk、required_scope、timeout、retry_policy、idempotency_support。每个参数定义类型、来源和对象作用域；返回区分 success、empty、failure、unknown，并附 source_ref/operation_id。
先列工具与副作用，再审查最小权限，封装一项只读调用；测空结果和错误后才设计写入。写动作绑定对象、字段、载荷摘要、前置版本、批准与幂等键；密钥由宿主秘密存储注入，不放工具描述或仓库。
工具返回裁剪关键字段、拍平无用嵌套，但保留错误、时间、单位与业务状态。脱敏在出域/落盘前考虑，日志不默认保留脱敏前敏感全文。

## 备用与验证

无写入授权输出操作草稿给人工；超时先用 operation_id 查询结果，不能立即重发。备用服务改变数据目的地须另行确认。
测试：缺字段/非法对象拒绝；敏感内容外发拦截；同业务请求重复不重复执行；HTTP 200+空结果不标完成；权限撤销后停止；读回与期望不符进入异常状态。
