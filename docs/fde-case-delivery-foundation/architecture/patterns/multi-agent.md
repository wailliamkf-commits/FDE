# MA：有必要才拆分的多角色协作

选用：角色能力/权限确实不同，子产物可独立验收，且单执行者已显示瓶颈。排除：固定小流程、共享文件多人同时写、没有仲裁标准。

## 结构与字段

主控→带依赖的任务契约→专家产物→校验/仲裁→汇总。共享黑板或消息传递都是选项，不能只让角色自由聊天。
编辑建议交接：task_id、role、inputs、allowed_actions、output_schema、evidence_refs、status、deadline、handoff_to。全局状态有唯一责任方；互相引用不算独立证据。

## 实施与故障

先画职责/权限矩阵和依赖图；定义每个角色的产物验收，再加入并行调度。共享状态用单写或版本控制，失败能定位到角色和步骤。简单冲突可用规则，专业冲突交有依据的审阅，高风险交人工；多数票不自动等于事实正确。
备用退回单一协调者顺序执行或人工分工，保留已确认成果。超时回收未完成任务前先核实在途副作用。
测试：角色越权拒绝；产物 Schema 不符不可交接；相互矛盾时不偷偷任选；重复派发不重复写；单角色失败不污染成功结果。
