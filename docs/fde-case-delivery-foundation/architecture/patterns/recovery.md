# RC：检查点、幂等与结果未知恢复

选用：长任务、异步动作、中断续跑。排除：不能提供真实状态查询时，不自动恢复有副作用的动作。

## 状态与字段

计划→持久化待执行步骤→提交工具→记录 operation_id→查询确认→提交检查点→下一步。
编辑建议：task_id、step_id、input_digest、action_digest、state、operation_id、result_ref、next_step、attempts。state 至少区分 pending/submitted/unknown/confirmed/failed；这是编辑后的契约，不是视频完整代码。

## 实现顺序

先定义成功证据和检查点原子写入；读取最近已确认状态，核对输入版本；对 submitted/unknown 先查远端结果；confirmed 跳过，确证未执行才可重试。写动作依赖服务端幂等/业务去重，查询也要考虑数据时效。
网络/限流按策略限次退避；参数错误先修正，权限不足转授权方；部分成功拆分保留，避免整批重做。并发工作者需要单写入者或锁/版本比较；本卡不提供分布式事务实现。

备用：停调度、冻结未决项和已成功项，交人工核查并恢复；真实外部副作用用补偿流程，不能宣称回滚文件等于回滚业务。
测试：提交后断网不重复退款/发信；检查点损坏拒绝盲续跑；输入版本改变使旧后续计划过期；部分成功不重做；取消时检查在途异步请求。
