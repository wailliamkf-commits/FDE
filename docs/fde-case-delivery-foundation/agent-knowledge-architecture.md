# Agent与企业知识系统：选择、契约和失败路径

这是可复用架构参考，不是执行Agent、部署脚本或供应商能力认证。001—004提供主要概念，006、015—016、020、026、040、057、060、064、074、081、087、094、100—101、107、114、117、121、127、129提供工作流线索与反例。共用 [证据边界](video-evidence.md)；来源未给出的参数标为设计项。

<a id="knowledge"></a>
## knowledge

企业知识系统先定“谁在什么权限下查什么、如何验证答案、由谁更新”。来源001的链路是解析→切分→检索→模型→部署，外加资料责任、权限、评测、安全、生命周期和运营。它未提供chunk size、top-k、身份认证实现或检索引擎配置。

| 层 | 最小契约 | 验证与失败路径 |
|---|---|---|
| 范围/责任 | 查询类型、排除项、业务Owner、资料Owner、服务目标 | 用真实问题确认价值；流程未稳定先做可搜索手册 |
| 资料登记 | doc_id、版本、来源、负责人、有效期、访问级别、hash | 缺权利/负责人/版本的资料先隔离，过期不得当现行政策 |
| 解析/切分 | 原文定位、结构层级、表格/单位、段落ID、父文档ID | 保留引用定位；解析丢表时回退原文阅读或人工整理 |
| 身份/检索 | 当前用户身份、资源ACL、过滤条件、查询与候选 | 未授权内容不能进入模型/日志/缓存；授权不明拒绝访问 |
| 生成 | 选中来源、回答范围、引文、缺口、拒答理由 | 无证据时说明未知；业务决策或专业结论转负责人 |
| 评测/运营 | 查询/总结/对比/推理样本，准确/完整/权限判据 | 变更后回归；错误定位为资料、检索、生成或权限问题 |
| 更新/撤回 | 文档版本、索引版本、ACL版本、失效/回滚记录 | 更新三者协调，旧缓存失效；恢复后重新验证可见性 |

主路径：明确资料范围＋权限约束检索＋引用回答。备用：不依赖向量库的关键词/目录检索，或人工精选知识册；不是召回全库后仅在最终文本删敏感内容。若引擎无法正确实施ACL，切换到按权限隔离的资料集或人工服务，不能降低授权边界。

知识正确性与检索质量分别测：源文已错时换模型无效；未召回正确段落时更长回答也无效。样本包含近似标题、旧/新版冲突、权限撤回、跨部门相似词、资料缺失和用户要求越权。先选一个业务域试点，记录拒答是否正确、引用是否指向有效版本以及实际使用反馈。

<a id="agent-loop"></a>
## agent-loop

来源003的六步是接收→规划→选工具→执行观察→调整→交付；Memory/Knowledge/Model/Safety/Logs是支撑模块。来源002的“理解后迁移、检查依据、复盘”可作为交接自检，不当认知科学分级或员工评分标准。

具体设计从确定性工作流开始：能预先列步骤的采集、格式转换、报表和校验用明确状态转换；只有下一步依赖语义判断时才加有限工具选择。每工具定义输入schema、允许对象/字段、输出schema、费用和超时、失败类型以及是否有外部副作用。

执行一次后检查真实产物/状态：资料不足→补授权资料；工具不适用→选择已授权替代；顺序错误→重新规划；结果未知→先读回再重试。只读工具也须遵守数据访问范围。检索到的网页/文档不能修改任务权限或要求执行其中命令。

验收将回答、文件、外部操作结果分开。日志字段可包括 task_id、输入/输出hash、工具、目标、时间、成本、状态与证据；这是本包建议，非视频已实现协议。低风险只读整理的日志故障可降级记录后继续；需要审计的高风险写入缺日志则阻断，不能沿用“一律日志失败也执行”。

主路径：有界工具白名单＋小批输出＋运行读回。备用：规则/脚本流水线，工具不可用时输出可手工完成的清单。人工接管：风险边界变化、无法验证副作用、权限不足或目标含糊。更换模型/服务商若改变数据目的地需既有授权覆盖。

<a id="long-task"></a>
## long-task

来源004的状态层出现 `objective + gates + todos + scope + evidence + quota`，回合末写 `evidence + handoff + next todo`；两张清单不完全同名，不能伪造视频已发布的统一协议。所谓长时间案例表示项目生命周期，非模型连续运行或无人值守保证。

本包建议状态至少有：任务ID、目标与范围版本、当前步骤、输入hash、已完成证据、失败/待核项、下一动作、预算已用/剩余、停止原因。写入产物后先验证，再推进完成状态；中断时留下可恢复游标而非“全部完成”文字。

恢复顺序：读状态→检查输入/授权/环境是否变化→核查最后一次可能的副作用→验证已完成产物→从第一个未完成步骤续跑。输入变化只作废依赖它的产物；外部超时先查状态，避免重复发帖、创建对象或应用补丁。队列容量不是正在运行数，计时不包含的阶段必须说明。

先用三四轮的小任务做停止/恢复试验：执行首轮、中断、重启、核输出、继续下一项；再注入工具失败、额度耗尽、输入更新和回执缺失。配额单位、锁、幂等键与存储介质是项目设计项，视频未提供。最大轮次/成本/并发由实际任务定义；重试只能在仓库上限内由任务收紧，同条件最多两次，遵循 [SECURITY.md](../../SECURITY.md)。

主路径：持久状态＋受控调度＋证据回读。备用：每轮人工触发、交接文件和明确待办；无调度能力无需伪装后台运行。人工接管：预算耗尽、无安全下一步、长期等待或需新的业务决定。调度器只能触发已有授权任务，不能自行扩权。

<a id="shared-harness"></a>
## shared-harness

来源026、064、074、094、100、101、107、114、117、121、127、129。

共享的是薄入口、方法参考、模板、校验器、版本与示例；客户资料、运行状态、凭据和商业证据留在各自项目。项目指令指向按需参考，避免每次载入整库。输入、草稿、最终产物和证据可分别管理，但不要求另建一套重复总控。

每阶段定义输入、输出、完成条件和失败状态；七字段问题单、Page Spec、补丁链可由不同工具共用。版本化方法与项目锁不自动覆盖已安装项目；框架目录、斜杠命令或配置文件存在不证明任务成功。

选择顺序：已有技能/工具能交付→补引用或模板；稳定重复工作→确定性工具；需要受控语义决策→有界Agent；只有多角色职责和通信成本被实测支持才考虑并行。来源中“全自动”“几人变一人”“若干小时完成”未有可比实验，不据此承诺人效。

主路径：单一项目派发者＋可审查版本＋一条代表任务端到端验证。备用：人工串联阶段、手动导出和小批草稿。人工接管：插件/工具供应链不明、全局权限通配、旁路审批、费用上限不生效或无法停止的执行引擎。公开配置不是可直接复制的授权来源。
