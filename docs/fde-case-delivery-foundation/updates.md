# 后续知识补充与版本

使用 [知识补充工作表](templates/knowledge-intake.md)，保留原来源与新增推断的边界。方法包独立版本不替代仓库版本。

## 流程

1. 原件留在授权的项目资料区；仓库仅存可分发的精炼知识、来源标识和通用模板。
2. 按哈希和来源版本检查重复，再记录页码/节点/时间戳及覆盖范围。
3. 候选资料先标 candidate。课程目录不是实现证明；视频讲解不是业务验收。
4. 评估能改变什么决定：问题适配、数据条件、实现方式、成本、风险或验收。只有标题重复则不新增技能。
5. 与现有结论冲突时列出双方证据；核查后将旧项标 superseded，并说明受影响方案，不默默抹掉历史。
6. 通过审阅分支更新索引和模板，重新验证链接、覆盖、manifest及回归测试，回读远端。
7. 新增适用内容可升minor；纠错升patch；字段/使用契约不兼容才升major。案例新增不自动更新客户项目锁。

## 待读资料

- ProcessOn“图灵AI大模型全栈开发”：目前可见目录与部分展开截图，不具备完整节点树；曾抓错的旧版不进入本包。
- 网页/视频采集：属于后续独立采集模块。采集方法与模型供应商解耦，不在本包自动下载、录屏或付费调用。
- 视频不能下载时：先区分“可合法播放”与“无权访问”。前者可以评估经批准的播放画面读取或用户录屏；后者请求授权素材。记录时间覆盖、音频缺失和未读区域，不能声称逐帧完整。
- 官方技术文档与新模型：注明核验日期、版本及必要实测；价格和兼容性不能永久写死。

删除原始资料前需要独立的清理授权、引用检查和可恢复记录。知识纠错不意味着删除本地PDF或历史资料。
