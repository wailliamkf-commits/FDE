# Agent、RAG 与 Skill 工程知识手册

本版聚焦视频展示的“如何实现”：组成模块、数据流、操作步骤、字段、策略、示例参数与故障处理，而不是重复“能带来什么效果”。正文按知识主题去重组织，仓库仅包含精炼知识与来源索引，完整视频观察记录不在分发范围。

来源口径：下文“视频提出/展示”均指此前保存的画面观察文字，不是新听取的口播。没有音频转写，原视频与截图现已由用户清理，无法重新检查像素。内容分为【来源记录】【跨视频归纳】【编辑提醒】；未显示的代码、参数、细节不补写成视频事实。此前报告里的“FDE 候选”是二次设计，不混入原视频知识。

## 1. Agent 基础架构：不是一个 Prompt，而是状态、决策和执行的组合

【来源记录】video-002，90–140 秒：九层名称为入口、理解与路由、规划、记忆、工具、执行、校验反思、人机协同、可观测与评测。原记录只对部分层展开，不能把所有层职责都当成作者完整讲过。

video-023，60–80 秒给出更紧凑的六组件：会话状态机、LLM 规划器、工具层、记忆、校验器、人工确认。分工是状态机管流程，LLM 管理解和生成，工具管事实和执行。不是让模型既决定权限，又执行动作，再自行宣布成功。

【跨视频归纳】可把这两种讲法连接为以下数据流，不代表某一视频里的原图：

需求输入 → 识别意图与补齐字段 → 形成任务计划 → 检查状态和权限 → 调工具 → 校验实际结果 → 更新外部状态 → 继续/重规划/人工接管 → 输出带依据的结果。

【来源记录】video-056，20–30 秒展示消息数组：role 标识角色，content 承载内容，数组顺序表示对话时间线；每次构造输入、调用模型、取得输出并追加到历史。40–70 秒以重新提供历史解释“模型记住前文”的表象。其“空数组不能生成任何文字”属于视频断言，不是本手册确认的通用接口规范。

### 固定工作流与 Agent 的具体分界

video-002，150–190 秒：固定步骤、确定性强的查询优先工作流；开放、多意图、多工具且需要动态决策的任务再用 Agent。结束条件包括目标完成、风险过高、信息不足、需要人工。

video-023 的订票流程是查询 → 筛选 → 确认 → 预下单 → 支付。自然语言理解可用模型，但支付前置条件、权限及状态流转不交给自由生成决定。

## 2. 需求变成可执行计划：目标层、策略层、执行层

【来源记录】video-025，80–140 秒的三层规划器：

- 目标层：把口语请求转为主题、范围、交付物、deadline 四项。
- 策略层：判断线性还是多分支、边执行边规划还是先列全局计划。
- 执行层：每个步骤指定工具、参数、成功判据和失败后的回退办法。

video-023，40–50 秒通过订票说明槽位填充：出发地、目的地、日期、时间范围、预算、直飞/中转、行李、退改、舱位、支付方式。缺字段就澄清；“都行”不等于无限授权，给时间优先或价格优先等默认策略后确认。

### 四种规划方式具体做什么

【来源记录】video-025，150–210 秒：

- CoT：线性拆解，适合路径较明确、串行依赖强的题目；视频将其与其他规划范式并列介绍。
- ToT：同一节点生成多个候选，对候选评估并剪枝；用于存在分叉、需要权衡的情况，代价是更多计算。
- ReAct：动作与反馈交替，根据工具观察结果决定下一步。
- Plan-and-Execute：先有整体计划，再逐步执行；发生偏差时重新规划。

【编辑提醒】这是教学分类，不等于所有方法具有相同的系统层级；不要求模型披露隐藏推理。可保存显式任务计划、工具决策摘要和结果证据。

### 任务依赖与重规划

video-025，220–310 秒：递归拆任务直到叶子可以通过工具执行；独立步骤以 DAG 表达依赖并并行。工具错误、中间结果不符预期、用户改需求都能触发 replan，从最近检查点调整，避免全量重跑。视频给单步 30 秒至 2 分钟的经验值，没有提供测量依据。

video-014，60–170 秒的复合需求案例：鞋小了要退款，同时查大一号库存与其他平台价格。规划拆出查订单/退款资格、退款申请、库存查询、比价和汇总。它展示“一个用户请求包含多条子任务”，不代表所有任务都能立即执行。

## 3. 工具调用：接口描述、执行校验、幂等是不同层

【来源记录】video-050，80–120 秒的五步链：意图识别 → 参数抽取 → 工具选择 → 执行并观察 → 按真实结果回答。

video-014，120–170 秒示例签名：refund_tool(order_id, reason)、logistics_tool(tracking_number)、price_compare_tool(product_id)。用 Function Calling 或 JSON Schema 约束工具与参数格式；视频没有交付这些函数的实现代码。

### 一个工具要描述到什么程度

video-038，70–210 秒：功能定位、参数语义与格式、适用场景、不适用场景。参数不能只写 user_id，要讲清是手机号还是内部 ID；查询权限是全部用户还是当前用户；空结果代表什么。

粒度判据：一动作一工具、参数可控、能力不要重叠。强绑定连续动作可合并；需要条件分支或独立重试的动作应拆开。返回结果裁剪为关键字段，减少无用嵌套和长文本，并保留执行状态与失败原因（220–290 秒）。

video-050 的退款描述进一步包含业务前置条件：已支付且未发货才可调用、是否可撤销、优惠券是否要联动退回。这个案例说明描述要包括副作用与依赖，不是只有“这个工具能退款”。

### 运行时三查与重复调用

video-035，120–150 秒：每次工具返回后查是否为空、是否匹配当前任务、是否满足业务标准。错误信息回传后允许有限次调整参数重试；检查“相同工具+相同参数”的重复调用。

video-050，200 秒特别区分失败和成功但空结果。没有查到订单，不等于已经完成退款。

video-023，90–140 秒：支付结合幂等键、预下单、二次确认；输出前核对航班号、时间、价格是否来自工具返回。工具失败或数据不足时不能生成一个“看起来合理”的成功结果。

【编辑提醒】同参去重不等于所有调用都可永久缓存；查询可能随时间变化。幂等应结合具体业务动作和请求身份，不能只靠模型记住“刚才做过”。

## 4. 业务状态机：用户改口时更新路径，不能直接重复操作

【来源记录】video-013，90–230 秒围绕拒收/退款展开：意图升级不等于把历史状态覆盖。用户改变处理路径后，要更新计划并确认已经发生的副作用。

操作序列：创建拦截工单 → 等待物流回执 → 触发退款 → 释放库存。

六态：待确认 → 拦截中 → 已拦截 → 退款中 → 已退款 → 库存已释放。

每次迁移须检查前置条件。视频用“拦截失败、已签收却又退款”说明失去约束会造成钱货两失。任务树、分支状态和结构化字段落库，不能依靠当前会话记忆。来源提到两条互斥规则，但本节所依据的汇总没有完整规则正文，故不补写。

【编辑提醒】这个案例是教学状态机，不是任意电商平台的标准退款流程。已发生的支付或发货不能靠“回滚对话”撤销，实际业务可能需要补偿动作或人工处理。

## 5. 防死循环、目标漂移与断点恢复

### 三种停止信号

【来源记录】video-016，90–200 秒：

1. 硬预算：理解问题、选择工具、执行工具、评估结果、生成回答、终止六种阶段；单任务最多 8 步后进入总结，8 为经验示例。
2. 信息增益：每次结果返回后检查是否新增信息；示例条件为连续两次无新增，或重复度超过 80%。
3. 目标漂移：比较原始问题与当前目标的 embedding 相似度；示例低于 0.6 时重规划。

video-008，180–220 秒另强调变量齐备即停；例如计算环比时所需两期数据与口径都取得，就不再无目的搜索。没有新增信息不能证明答案正确，只能说明应停止或改道。

### 五层目标约束

video-030，70–290 秒：目标锁固定核心任务；角色锁限制职责与权限；上下文锁过滤工具噪声；子任务锁执行前检查和总目标的关系；输出锁检查最终是否真正回答原问题。

销售分析例：允许取数、分析、可视化、建议，但不允许因 SQL 慢擅自修改数据库配置；最终要求下降原因和三条建议。输出校验失败后最多两次重试是来源示例。

### 持久化与恢复的字段

video-040，70–170 秒要求外存：任务 ID、步骤序号、本步动作、参数与返回摘要、下一步计划。网站采集案例把 100 个网站拆为独立子任务，每完成 10 个保存检查点，记录已完成项、失败项、产物位置、续跑起点。

写操作用唯一键或去重标识；不支持幂等的外部工具，先确认之前动作状态。恢复不是“再发一遍所有请求”。

错误分类（220–290 秒）：网络/限流等可重试；参数/权限问题不可直接照原样重试；部分成功则保留成功产物，把失败项另入队。视频给最多重试 3 次，无通用适用性证明。

## 6. 记忆架构：存什么、什么时候写、如何更新、怎样取回

### 三类记忆和四种载体不是同一个分类

【来源记录】video-001、007：短期记忆保留当前对话，长期记忆保留偏好/事实/历史事件，工作记忆保存任务中间产物。

video-055 则按载体讲会话元数据、结构化用户档案卡、近期对话摘要、滑动窗口。前者偏用途，后者偏组织方式，不宜硬凑成同一套互斥分类。

### 写入时机与冲突更新

video-007：对话结束后抽取总结；明确“记住”或重要事件即时写入；后台归并去重。示例把“下周去东京出差”抽为行程、时间、地点，而非全量聊天记录直接入库。

旧偏好“喜欢甜咖啡”与新信息“戒糖”冲突，需要更新或建立时效关系，而不是追加两条都当现状。原视频没有提供完整冲突判定算法。

### 取回策略

video-001/007：语义相似度、时间衰减、重要性加权、关键词+向量混合检索。重要事实不应与随口闲聊同权；专有名词用关键词补充语义召回。来源没有给衰减公式、权重或 TopK。

video-055：精确用户字段和模糊语义摘要应区别处理；Ledger 存事件账本，Views 生成任务视图，Policy 定义写入/读取/遗忘规则。Valid Time 是事实有效时间，Transaction Time 是录入时间，用来区分“事情何时成立”和“系统何时知道”。

【编辑提醒】来源把视图过滤称为遗忘；这不是物理删除。只追加账本也不应成为保留所有敏感信息的理由。医疗、隐私等重要信息不能仅凭模型自动打分决定处理。

## 7. 上下文压缩：保留任务骨架，而不是仅缩短字数

【来源记录】video-040，180–210 秒的简单做法：每 5–10 步压缩，摘要保留已完成、失败及重试队列、当前进度。视频示例数字存在不自洽，不可拿作真实运行指标。

video-061，100–350 秒提出分级方法：

1. 大件外置：完整文件放本地，消息保留缩略与位置；首次决定全量还是缩略。
2. 清除死胡同对话：按整轮删无效试错，并记录释放空间。
3. 清理旧工具快照：保留近期结果，不动任务骨架；示例只留 5 条。
4. 选择性摘要：压缩早期探索，保留设计和编码阶段的重要内容。
5. 完整纪要兜底：辅助总结者只总结、不调执行工具，结束后恢复最近文件和相关历史。

370–423 秒另讲增量笔记：持续抽取新增要点，后续压缩复用这些笔记；自动压缩连续失败 3 次停止尝试。

【编辑提醒】9 段式纪要、缓存热/冷的服务端处理都是来源描述，不能据此假定当前 Harness/API 支持。约 100% 缓存命中等未验证。删除旧消息也可能影响缓存与可追溯性，不能同时承诺任意改历史且缓存不变。

## 8. RAG：入库链和问答链分开理解

【跨视频归纳】来源 video-004、006、017、029、060 可整理为两条链：

入库：原资料 → 解析结构 → 按语义与版面切块 → 附上版本/页码/权限等元数据 → 建关键词/向量索引。

问答：用户问题 → 改写及消歧 → 查询过滤 → 多路召回 → 融合 → 重排 → 选择上下文 → 生成有引用的回答 → 校验。

### 为什么不是只用向量

video-006，20–110 秒：语义匹配可处理同义表达；日期、编号、专有名词等精确字段另用 BM25。两路分数尺度不同，直接相加可能失衡；该片建议 RRF 按排名融合，再交叉编码器逐对评分，示例从 Top50 选 Top5。

video-029，120–180 秒也讲双路召回，但允许加权融合，按语义/精确场景调整权重。两个视频侧重点有差异，不能归并成“线性融合一律禁止”。原记录没有提供一套统一权重或归一化方案。

### 查询改写、父子块与时效

video-004，90–160 秒：将“那病假呢”补全指代；按标题切块；检索用较小子块，生成取父块上下文。元数据保存部门、版本、生效日期、权限、文档类型；冲突时说明使用哪个版本。

video-006，120–200 秒给时间过滤示例和 200–500 token 切块经验值；库中缺资料时再走外部来源。时间过滤必须对应业务事实时间，不能把所有旧文档无差别排除。

### 多跳检索

video-005，150–240 秒：先找中间实体并核验年份/奖项/实体，再以该实体查属性；保留每一跳证据。单跳限制下，视频提出预建实体关系或多路并行检索。示例要求三字段同片段出现，是该案例的严约束，不是所有任务的通用规则。

### 如何定位答错在哪一段

video-004，60–80 秒：正确资料没召回，查检索；有召回但排序太后，查重排/上下文选取；正确资料已在上下文仍答错，查生成与指令。先保存问题、召回、排序、上下文和答案，而不是只看最后一句。

## 9. PDF 结构化：页码、表格关系和引用都要保留

【来源记录】video-060，60–310 秒展示四层：

- 解析：原生 PDF 提取文字和坐标；扫描件走 OCR；图文混排考虑视觉理解。
- 结构还原：标题层级、表格行列、图片与上下文、页眉页脚。不是把全页变成一条扁平文本。
- 切片索引：同标题段落关联；完整表格结构保留；图片和说明绑定。字段包括文档 ID、页码、章节、表格编号、图片说明、时间戳、版本号。
- 工具访问：search_pdf 搜索、read_page 读页、extract_table 提表、analyze_chart 分析图表、quote_source 给引用。简单查询一次搜索，跨年度毛利率比较则搜资料、提表再比较。

320–379 秒：检查命中页码、表格数值、OCR 漏错字、图表理解，每个结论可追到页/段/原文片段。旧汇总“350 秒后无记录”为整理错误，group-007 实际保存了末尾三帧文字。

【编辑提醒】不能照搬来源“禁止文本抽取+OCR 组合”的绝对说法；关键是结构与对应关系是否丢失。正文提到的工具名称不是已安装工具。

## 10. 评测与观测：指标各自检查什么

【来源记录】video-057，70–130 秒：Context Precision 检查召回中有用内容；Context Recall 检查必要依据是否齐全；Faithfulness 检查答案是否忠于依据；Answer Relevancy 检查是否回答实际问题。视频没有给精确计算实现。

示例：“如何申请退款”却回答“退款政策是什么”，可有事实依据仍答非所问；文档写 3–7 工作日却承诺当天，是依据不支持的生成。

220–240 秒：组件评测看 Hit Rate/MRR/NDCG；整链看上述四项；业务层看人工通过率、满意度、追问、bad case、转人工。指标组合用于找排查方向，不唯一确定根因。

video-020：测试题取自真实问题，加常见/边缘/诱导样本，示例比例 7:2:1；每题标标准答案和参考文档，规定完全正确/部分正确/答非所问评分。缺数据时 video-057 提议合成题，但必须人工抽检。

video-046，60–180 秒要求串起用户输入、意图、任务拆解、工具选择、参数、返回、结果生成。HTTP 200 不等于任务完成；监测回答质量、工具失败、任务完成、用户点踩与异常调用频次。

【编辑提醒】来源提到保留每轮思考、完整参数和原始返回；实施时应改为必要的显式决策摘要与脱敏证据，不要求隐藏思维链，也不默认落盘敏感原文。

## 11. 多 Agent：角色契约、协调者、共享状态

【来源记录】video-014，240–260 秒给主控加售后/物流/价格专家拓扑；用消息传递或黑板共享信息。

## 12. Skill 路由：从模糊名称改为可区分的触发条件

【来源记录】video-058，110–290 秒的四步：

1. Description 写“何时用”。“负责生成 PPT”区分度低，改为汇报、融资路演、季度总结等触发场景。
2. Skill Tree 先按研发/运营/市场/财务分域，再在域内选能力，不一次塞全量目录。
3. 补 when not to use，写相邻技能的排除边界与负例。
4. 数量扩大时，两阶段路由：用户请求 → 向量粗召回 → Top-N 候选 → 模型精排 → 选技能。来源没给 N 的数值。

video-055 还把成功执行轨迹固化为含步骤、参数、校验规则的程序性记忆。这里的关键不是收集更多 Prompt，而是可复用执行知识和清晰调用边界。

## 13. 两个完整案例保留“怎么做”

### 会议纪要与任务分配

【来源记录】video-010，90–290 秒：VAD 切有效语音 → pyannote 等分离说话人 → Speaker 标签 → 分片 ASR → 清洗并按话题/说话人分块 → 先生成会议主题/结论/争议 → 再抽待办。

### 热点视频理解与脚本生成

【来源记录】video-018，120–410 秒：先定义热度是点赞、播放还是综合指标；注明获取来源。数据获取提供官方接口、第三方 API、浏览器可见信息的降级思路。内容理解分 ASR 文案与镜头边界关键帧两条链，再合并总结。
