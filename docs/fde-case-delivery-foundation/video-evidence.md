<a id="evidence-levels"></a>
## evidence-levels

| 身份 | 本包表达方式 | 下游使用边界 |
|---|---|---|
| 历史视觉报告 | “报告记录”“画面文字自述” | 可提出问题、定位来源；不能证明保存、上线或效果 |
| 作者判断/经验 | “作者主张”“案例参数” | 是待检验假设；固定字数、密度、锚文本比例、周期不成为通用门槛 |
| 本包工程归纳 | 方法步骤、输入输出、主备路径 | 为拟议做法，实施前按项目验证；不声称视频展示过代码 |
| 独立官方核验 | 有官方URL、核验日期和明确适用平台的记录 | 按当日规则更新；Google规则不扩展为所有AI平台规则 |
| 项目实测 | 有测试输入、环境、产物、读回和失败记录 | 仅对该范围有效；本次未实施客户站或执行Agent |

本版不复制客户域名/姓名、业务结果数字、付费报价、原始询盘或个人叙事。保留技术字段、可复用机制、通用产品/协议名称，以及确有教学价值且标为案例值的处理参数。

<a id="retrieval"></a>
## retrieval

1. 按 ID 查索引，核对 `revision_of`、`disposition` 和 `uncertainties`，再打开 `methods` 指向的具体章节。
2. `technique` / `details` 为脱敏提炼；章节中的步骤为工程归纳。涉及原作者说法时，回到私有原件并比较 `report_sha256`。`source_sha256` 不证明原片仍可读取。
3. 使用当前规则之前查官方资料；采用历史阈值之前定义本项目采样和验收。官方纠错与历史来源并存，不修改历史报告的身份。
4. 输出来源 ID、方法路径、当前假设、待核项与验证方法；缺数据时选择较低依赖路径。

<a id="known-conflicts"></a>
## known-conflicts

- 001 的 frame-011/012：叙述时序与结构化索引冲突。002 尾组帧号/时间也错位。可确认文本不一致，不能在原图缺失时自动改时间并宣称修复。
- 模拟 SERP、第三方工具估算、GSC 窗口均位及当前排名不是同一口径。缺失、跟踪超界、零和未收录分别记录。
- 057 选词输入输出计数不一致；087 批处理自述与实际重定向状态不一致；105 迁移进度完成却存在未解释输出。它们进入反例，不能当成功交付。
- 028/030/102 的 FAQ 结构化数据教程与当前 Google 展示政策需要分开；内容问答仍可服务读者，不能沿用历史富结果收益承诺。
- 123/133 的 Markdown、llms.txt、实体知识建议要区分可读取性、索引、引用与转化；126 的 Discover 不能变成 Gemini/AI 引用统计。
- 外链比例、工具评分、所谓惩罚/沙盒、停广告与掉自然流量、全AI内容与断崖之间的因果均未由本批证明。原报告中的安全设计或SEO推导也未自动升级为已实现机制。
