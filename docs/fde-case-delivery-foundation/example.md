# 合成示例：库存异常只读试点

这是构造的演练，不是PDF中的真实企业或已部署结果。

## 简短需求

“每天提醒哪些SKU可能缺货，先别改ERP或广告预算。”
合成条件：客户允许每日导出CSV到指定项目目录，尚未确认API权限；未确定缺货阈值、SKU匹配口径或滞销定义。

## 诊断与选择

目标是减少异常发现延迟，不是先做Agent。参考DW-20的只读分离与DW-22的跨系统依赖，但不复制案例收益。
最先确认SKU主键、库存口径、在途是否计入、预警责任人与真实基线。

A：每日CSV → 字段/重复SKU校验 → 客户确认的规则计算 → 本地异常清单 → 人工处理。无需LLM计算库存。
B：CSV格式不稳定时，固定少量SKU，用人工确认的表格模板批量计算；降低覆盖，不降低来源追溯。
C：缺字段、源文件过期或规则未确认时，仅报告数据不可用并回到原人工盘点流程；不输出看似正常的“无缺货”。

## 假设与验证

用明确标为合成的正常、重复SKU、缺字段和过期样本试验；业务阈值确定前不宣称预测准确。
验收至少要求：每条异常能定位源行，缺失数据不能被当作零库存/正常库存，异常流程能人工接手。
上述是验收设计，本示例没有附带库存检查代码，也未运行客户数据。

## 权限与切换

允许项目内草稿，不允许ERP回写、广告调整或外部自动通知。
以后如改成API实时读取，先做独立访问预检；如改为外部飞书通知或云端模型，需要核对新数据目的地与批准。

## 价值

先测人工发现延迟和处理时间，再同口径回访。案例报告的工时下降不能填成本项目收益。
