# GitHub 私仓交付与接收

## 交付范围

正式来源为 `https://github.com/wailliamkf-commits/FDE`，保持私有。交付物是六项技能、通用模板、局部检查脚本、测试、安全规则与完整性清单。插件清单和安装器仅为可选适配，交付不要求维护者安装、购买团队套餐或商店上架。

仓库从干净文件快照建立，后续保留正常版本历史以便审计和恢复；“clean”不代表每次更新都删除历史。真实客户文件、账号凭据和项目运行记录留在各自获准工作区，不放入工具箱仓库。

## 接收步骤

1. 由所有者通过 GitHub 的正常授权流程授予接收者所需的最小权限。读取不足时报告具体阻塞；不索取聊天中的 Token，不为方便下载而公开仓库。本次交付不自动邀请任何新成员。
2. 从可信交接取得仓库地址、完整 40 位提交和 MANIFEST SHA-256。下载或检出该固定提交，保留目录结构及隐藏的配置文件。浮动 main 仅是开发入口，不自动升级现有项目。
3. 先使用包外可信工具核对来源与文件，再阅读 START_HERE.md、SECURITY.md 和 catalog.json；审阅脚本后按 README 的隔离校验、测试和合成演示步骤验证。所有证据放在工具箱目录外，避免破坏精确文件树。
4. 报告实际取得的提交、清单哈希、文件一致性和实跑检查。无法执行的检查记“未执行”；只读文件不能替代测试。哈希匹配只证明一致，不证明代码可信或业务正确。

## 接收后的使用

只需参考流程时，在有文件读取能力的环境中按当前任务选择所需 SKILL.md 及其引用资料；读取和按流程使用不等于原生安装，不自动获得任何工具或权限。

需要项目级原生调用时，才阅读 INSTALL_AND_WORK.md，核对宿主支持、用户授权和冲突预览。当前接收者没有安装能力，不阻塞其他可用任务。

## 三项独立结论

- 仓库交付：私有状态与仓库身份已回读，远端固定提交及文件树与已审阅、已测试的交付物一致。
- 原生调用：只有在指定宿主实际发现并调用技能后才能通过；默认不在本次范围，仍保留“未验证”的事实。
- 业务验收：在具体项目对照冻结的输入、范围和成功指标验收；通用模板、脚本单元测试和合成演示不能替代真实业务证据。

## 更新和恢复

变更经独立分支、差异审阅、清单再生成与回归测试后，用 PR 更新本仓库；只推送已审阅文件。每次交付保存新提交与清单摘要，旧版本不自动迁移。需要回退使用时，重新取得先前已审阅提交，不重写或强推历史。
