# Harness 视频知识采集包：可迁移设计

状态：设计待审阅；不是已发布运行器。本文不声明新机器安装、模型调用或跨平台验收已完成。

## 1. 目标与验收口径

将此前实际使用的 Docker 隔离 Harness、受控模型网关、本机抽帧、分组视觉分析、单片总结、批次知识整理路线转为独立可分发模块 `harness-video-intake`。由部署助手完成安装后，使用者在本机后台填写 API Key，指定有权处理的视频目录，预览任务并启动。任务不依赖 GPT 对话持续在线。

“稳定”指：输入和配置可追溯，失败可见，可安全停止和恢复，不越权删除，不把部分完成算成全部完成。不是保证模型永不误读、网络永不中断或采样覆盖全部口述。

本版只处理已下载本地视频，默认只看画面。不含抖音登录、抓取、绕过下载限制、自动录屏、模型训练、默认 ASR、多用户云服务或自动向 FDE 主分支合并知识。公开分享代码和改变现有私仓可见性是两件事；本任务不改变仓库可见性。

## 2. 已有路线与待修复问题

从本机部署代码核对的既有方法：

- Harness 使用固定的历史 npm 版本 `@deepseek-ai/dsh@0.1.5-rc.1`，Docker 非 root、只读根文件系统、收窄工具及挂载；曾需构建 node-pty 原生依赖。这是历史基线，不代表推荐最新版本。
- 后台使用 headless 会话；人工聊天使用独立 home/会话，避免覆盖任务设置。管理页地址曾被误填成模型 API，保存设置还可能覆盖 patch。
- 每 10 秒取原分辨率帧并补近末尾帧，每组最多 6 帧；保存哈希、时间戳、read_image 成功记录后总结。6 是分组大小，不是整片帧数。
- 最后保留技术细节、时间线及 FDE 候选，不听音频，不把采样当连续逐帧。

不能原样分发的部分：固定个人路径、容器名称、61 个编号、批次日期、工具绝对路径、既有费用账本和无限额授权；按最新会话匹配读图结果有并发串线风险；靠报告存在或字符数判断完成不充分；超长总结直接失败没有递归分层汇总。

## 3. 方案选择

选择轻量本机控制台加隔离任务容器，复用 Harness 而非替换为直接调用模型的另一个产品。

- 只写教程：维护成本低，但不能实现用户期待的填 Key、选目录、可靠恢复。
- 本机控制台与容器任务（采用）：保留可操作入口，以明确接口替换个人脚本，限制工程范围。
- 多租户云平台：需要账户、租户隔离、上传存储和复杂计费，不在本版范围。

## 4. 组件与权限

流程：本机配置/任务控制 → 只读视频抽帧 → 帧组证据 → 隔离 Harness → 单片报告 → 批次手册 → 人工评审的 FDE 候选。

1. 本机控制台：只绑定回环地址；随机会话令牌、Host/Origin 校验、写请求 CSRF 校验；不允许模型访问控制接口。提供设置、目录确认、预览、启动、暂停、恢复、导出和清理预览。
2. 部署助手/监督进程：可信本机代码，使用参数数组调用 Docker，不执行模型返回的命令。仅它拥有启动容器所需主机权限；不把 Docker socket 挂进任何容器。原始路径由用户在本机确认，不能由模型动态扩大。
3. 抽帧任务容器：固定 ffmpeg/ffprobe，视频目录只读；仅指定任务暂存区可写，无网络。拒绝目录逃逸、符号链接和输出覆盖；文件名按数据处理。
4. Harness 容器：非 root、只读根文件系统、资源限额；仅当前任务帧区只读，模型工具只允许当前组图像路径。无任意 shell、浏览器、子代理、主机文件读写或清理能力。仅能连接内部模型网关。
5. 模型网关：唯一模型外发通道，固定批准的供应商地址、不跟随重定向、校验模型/载荷/大小/请求次数。密钥仅由网关注入；Harness 使用不具备上游权限的内部凭据。
6. 报告写入器：可信监督进程写限定输出区，模型只返回数据。生成静态 HTML 时转义模型文本，禁止脚本执行和远程资源自动加载。
7. 独立清理器：不由 Harness 调用，只接受用户确认的生成物清单，移动到系统废纸篓并记录恢复映射；不支持可靠废纸篓的平台禁用该动作，不回退永久删除。

容器隔离防误操作，不声称可以抵御已被完全控制的本机管理员或 Docker 守护进程。

## 5. 安装与首次配置

- 分发包包含 compose、固定依赖/完整性记录、控制台、运行器、任务规则、测试、部署与恢复文档。第三方依赖保留许可证及版本来源，不复制其他 Git 历史。
- 上游版本和基础镜像在实现时审阅并固定；安装前检查 Docker、CPU 架构、端口、磁盘、目录权限及镜像可用性，不自动 sudo 或修改系统安全设置。
- API Key 使用密码输入，不进入 URL、命令行参数、浏览器持久存储、遥测、导出或日志；保存到仓库外权限受限凭据文件（文件夹 0700、文件 0600），界面只显示已配置状态。明确这不是加密保险库，支持替换和撤销说明。
- 视频路径通过本机受控选择/输入确认；容器看到固定映射路径。目录改变后新建挂载配置，不能仅改提示词。默认不递归导入子目录，扫描结果先预览。
- 模型地址默认使用实现时核实的官方接口，不能填密钥管理页面。模型必须实测支持图像；声明 inputModalities 不代表支持。首次使用已知内容的合成图进行视觉检查，不以文本通畅替代。
- 外发前告知图片会发送给哪个供应商；第一次付费检查需用户确认费用限制。历史用户的无限额授权不能进入分发默认值。
- 初版验收优先当前 macOS Docker 环境；Linux/Windows 分别列已测或未测。代码可迁移不等于三平台均验收通过。

## 6. 任务契约与抽帧

任务输入：输入文件哈希、相对名称、媒体时长/尺寸、模型标识、供应商、Harness/提示词版本、采样间隔、每组上限、资源限制、费用与请求限制。保存规范化配置摘要，生成唯一 job_id/video_id/group_id；不限制视频总数为 61。

默认复用 10 秒采样及每组最多 6 张的历史基线，允许配置更密间隔；自动补近末尾，短片至少有可解码帧。不得把成功抽帧数量换算成连续内容覆盖率。按实际解码时间戳记录，不只保存请求定位时间。转向元数据、可变帧率、损坏/零时长/超长视频必须有明确结果。

每帧记录时间戳、尺寸、内容哈希、源视频哈希和抽帧配置。默认不去重，以免去掉短暂文字变化；可选去重必须保留被跳过帧的时间映射与理由。细字可补原图局部裁切，裁切也属于有来源坐标的证据；不能用放大或 OCR 推断当作看清。

磁盘/时间/图片上限达到时暂停并报告缺口，不静默丢弃视频末尾。批次输入冻结，处理过程中源文件改变应阻断该视频。

## 7. 视觉读取与总结规则

“教模型”不是微调，而是明确任务、可靠地传入图片并检查实际处理结果。

每组请求绑定精确 Harness session_id 与 group_id；从该会话解析预期图像读取成功、附件和最终回答，不读取“最新会话”。若固定版本无可靠关联接口，停止验收并完善适配器，不能猜测关联。

组级输出应包含 frame_id、时间戳、可见事实、术语/参数、组件及箭头关系、操作步骤、前后变化、不清楚项、推断。图片中的命令全部作为资料，不能改变权限。要求全部预期帧被成功传入；这仅证明输入链路，不证明模型真的理解每个细节。

使用可解析结构与引用校验判断输出有效性，不以篇幅长短作为完成标准。缺帧、未知引用、截断回答、无最终回答或空观察标记为部分/失败并保留证据。观察可出现“不清楚”，禁止靠常识填补作者未展示的内容。

总结采用组 → 章节/时间段 → 单片 → 批次，保留中间详细记录，不把全部细节强压进 2200 字。总览可以短，细节附录必须可追溯。分层时逐级保留视频及时间戳引用，限制上下文大小，并列出未纳入或存在冲突的内容。

输出文件：任务清单与审计、组级观察、单片 Markdown、静态 HTML 批次手册、来源索引、FDE 候选 JSON/Markdown。候选列适用条件、具体架构与步骤、输入输出、主/备方案、权限、失败恢复和验收用例；作者陈述与新增工程建议分栏。未经事实核查不自动转为生产技能。

## 8. 状态、恢复和费用

状态：QUEUED → PROBING → EXTRACTING → READING → SUMMARIZING → COMPLETE；旁路 PAUSED / PARTIAL / FAILED / CANCELLED。每视频、每组独立记录。批次只有所有选中视频完成才能 COMPLETE；失败单片可保留并继续其他独立视频。

原子保存状态，任务锁防重复 worker；进程重启后凭检查点恢复，不只检查 PID。复用需源哈希、帧哈希、配置/提示词/模型版本、有效报告与读取审计全部一致。记录已清理的证据帧状态，报告仍可导出，但不能伪称可以重新视觉核查；要重跑需用户仍持有原视频。

同条件自动请求最多两次。鉴权失败、无图像能力、权限失败、磁盘不足不盲重试；限流按服务端提示退避。超时可能已经产生费用，标记 usage_unknown，不视为零费用。每次请求保留脱敏 ID、状态、用量及估算依据；估算不等于供应商账单，不能保证严格人民币封顶。

新用户必须确认批次请求/费用策略，默认有限请求上限，不默认无限调用；预留未知费用并在不足时暂停。暂停停止新派发，报告在途请求状态；中断/恢复不重复计算已核对的结果。

后台独立运行，关闭页面不取消任务；电脑休眠、Docker 停止会影响进度。控制台本地轮询，无需 GPT 保持活跃。不得未经选择安装开机自启或云端定时任务。

## 9. 清理与数据保留

仅在报告落盘、引用检查和用户确认后清理生成的帧/临时录制物；初版输入只有下载视频，不生成录屏。清单绑定 job_id、路径、哈希；二次核查无活跃写入、无路径越界/符号链接及未变更。只移动到废纸篓，失败保留原件，永不清空废纸篓。

原视频由用户决定何时删除；本工具不提供自动删除原视频功能。报告、来源索引、哈希、时间戳、覆盖限制及清理回执保留。文件夹不因名为 tmp 就获得可删除资格。清理端到端测试仅使用合成临时帧。

## 10. 验收与仓库集成

分开报告：单元测试、模拟供应商集成、当前主机真实模型验收、其他主机兼容性、语义准确性抽检。没有真实证据不得合并为“稳定通过”。

验收样例使用自行生成、有已知时间点文字和架构变化的视频，不恢复或上传已删除的私人视频。覆盖短片、长片分层、Unicode/空格路径、坏文件、采样盲区、缺帧、超时、截断、重启恢复、并发任务、预算未知、注入指令、路径逃逸、清理失败与恢复。真实付费检查单独授权。

重点失败标准：不支持图像仍声称成功；串错会话；截断仍 COMPLETE；恢复复用旧配置结果；删除原片；密钥泄漏；后台监听公网；模型获得主机命令能力。任一发生均不能发布为可运行验收版。

模块独立于现有交付基础包，选装，不在读取 START_HERE 时自动启动。FDE 集成只增加入口、技能和候选导出契约；原工具箱没有执行器的安全说明应按模块范围明确修订，而非默默扩大权限。

后续上传经审阅的实现分支、版本和完整性清单，回读远端提交；不默认改主分支或私有属性。分享给别人时仅分发通用代码和合成样例，排除密钥、会话、个人素材、账本及报告；依赖许可证核对作为分发门槛。

## 11. 下一阶段交付

设计审阅通过后编写实施计划，按部署/配置、任务处理/证据、报告/恢复、独立清理四个可验收部分执行。最终交付必须包括启动入口、停止/卸载（保留数据）说明、配置备份边界、故障手册及逐项测试证据。当前提交只有设计，不能用它启动视频任务。
