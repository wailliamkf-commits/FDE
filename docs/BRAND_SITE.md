# 品牌独立站方法模块 · 1.1.0

新增按页面职责、证据补丁、内链/跳转、多语审校、媒体、迁移和表单分支执行的 SEO 工作包，见 [SEO / Agent 网站交付](SEO_AGENT_DELIVERY.md)。原市场、视觉、业务适配和发布边界保留；新增方法不等于目标网站已实施。

入口：[fde-brand-site](../skills/fde-brand-site/SKILL.md)。本模块将多轮品牌网站研究、页面升级和发布故障中可迁移的决策方法重新编写为通用流程。不是聊天记录导出，不包含真实品牌数据、后台ID、产品成本、证书、图片原件或生产配置。

## 从什么问题进入

| 当前任务 | 读取 | 输出 |
|---|---|---|
| 接手不同类型客户项目 | 业务模式适配 + 模型调度 | 模式/对象/转化/履约配置，由当前可用前沿思考角色选择执行模型 |
| 找竞品、决定定位/路线 | 市场与竞品 | 样本池、观察/推断分离、采用/舍弃理由 |
| 首页太像表单、详情/系列单薄 | 架构与内容 | 页面职责、模块与主旅程、数据/证据缺口 |
| 图多但无品牌、手机错位、动效不足 | 视觉与交互 | 图像角色、原创简报、响应式与组件状态契约 |
| GEO/SEO/博客/自然流量验证 | 发现与增长 | 意图到页面、主题/内链、测量与有界实验 |
| 实施上线和后续优化 | 工程发布维护 | 分层验收、公开回读、优先队列、回退与存储 |

技能内有5份可填写工作表、明确合成演练情境及官方来源索引。按需要复制模板到实际项目；不用同时填写全部模板。工具仓库不自动安装到当前账户或客户项目，也不新增浏览器、API、调度器或生产权限。

这不是珠宝或高端电商专属方案。先选择零售、定制、B2B获客、服务预约、订阅/软件、内容/教育或必要混合模式，再改变页面模块、视觉证据、CTA、事实字段、失败状态与指标。技术栈和品牌审美不预设。

思考角色采用本轮获授权、可用且适合任务的前沿模型，由其选择最低合理执行层级；后续代际变化通过能力核验和代表任务评测处理，不修改方法中的固定型号。宿主不支持路由时只交付工作单并如实标注，不声称已自动切换或节省额度。

## 方法中的关键教训

- “有模块”不同于“顾客能回答问题”；首页不是默认长表单。
- 图片至少区分身份、场景、比较、理念、真实证据，不能用生成图承包所有角色。
- 竞品选择横跨商业替代、搜索意图、相邻客群和视觉参考；品牌知名度不等于页面因果证据。
- 控件存在不是交互已测；截图漂亮不是保存/上线；本地PASS不是商业READY。
- 素材上传、逐文件保存、正确主题、公开回读和实屏测试是不同的关口。
- 一个店铺的色彩、具体交期、SKU数、主题ID、原料价格或三场景文案不推广为所有品牌标准。
- 无证据不扩大；有证据优先最小修改；当前版本通过就停止，把效果验证留在真实运营周期。

当前包装测试验证入口/链接/版本/安装保持性，不证明技能的全部行为或商店经营效果。发布回执记录在仓库之外的交接材料；后续按审阅分支更新，不自动升级已有项目锁。
