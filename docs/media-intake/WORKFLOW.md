# 媒体读取与知识整理流程

处理视频、单图或多页图文时使用本流程；验收细则见 [QUALITY.md](QUALITY.md)，单项评审使用 [MEDIA_INTAKE_REVIEW.md](../../templates/MEDIA_INTAKE_REVIEW.md)，知识条目参考 [JSON 示例](../../templates/media-knowledge-claim.example.json)。先遵守仓库 [START_HERE.md](../../START_HERE.md) 和 [SECURITY.md](../../SECURITY.md)。

本包提供流程、质量标准和模板。真实抽帧、OCR、模型网关、运行调度、镜像及清理代码留在项目外部运行环境；本包没有新增收费、后台运行或删除执行器。历史试读支持采用这些检查方法，同时暴露了漏读和错误归纳；没有由此证明任意宿主已能运行，也没有证明任何素材全集已经处理完毕。

## 1. 冻结任务和宿主能力

沿用项目现有总控、事实源与批准范围，指定一个有效控制者。记录宿主版本、已静态审阅的运行代码版本、可用工具、用户允许的数据目的地、模型、费用和清理范围。授权未给出的部分保持未授权；本模板不能扩大既有授权。

宿主分别实测：媒体探测、抽帧、OCR、成功图片附件、会话归属、实际返回模型、费用结算、断点读取和镜像回读。使用 `NOT_CHECKED / AVAILABLE_READ / AVAILABLE_WRITE / BLOCKED / UNKNOWN` 记录能力及证据；文件存在、导入成功、UI 在线、合成测试通过均不能代替真实调用证据。敏感素材先确定是否允许送往所选模型服务。

**完成条件：** 必需能力已有当前证据；未知只阻止依赖它的步骤；执行范围、费用规则、单控制者和停止条件可被回读。没有模型元数据时保留 UNKNOWN，不能从自我介绍猜型号。

## 2. 清点素材并固定版本

在项目专用索引中记录每份原件的逻辑标识、相对位置、SHA-256、字节数、媒体类型和探测结果；视频增加时长、分辨率、音轨与字幕流状态。文件名、下载时间和目录名只是标签，不能推定作者、拍摄日期、内容主题或商业模式。实际源路径留在项目私有记录，不进入通用仓库。

相同内容哈希可复用已核验结果，但仍保留所有来源别名、页序和引用关系。同名不同哈希是新版本；画面相似不是相同内容。记录 `revision_of` 或等价关系，不覆盖旧版证据。输入、抽样策略、提示词或模型配置变化时生成新版本，旧报告标为被替代或待复核，不能无条件命中旧缓存。

多页图文先建立材料组、原始页序和缺页清单。确定页序应有来源依据；不确定时写未知。照片序号、抽帧序号与材料的物理页码分开记录。

**完成条件：** 原件、重复项、拒收项、未知类型和待分组项均计入分母；每个工作单元可追溯到具体原件版本。

## 3. 准备证据并标明覆盖

| 材料 | 准备方式 | 必须保留的边界 |
|---|---|---|
| 视频 | 分时间段均匀抽帧，结合场景变化与文字密度补帧；保存真实申请的秒数及时间基准 | 抽帧不是连续观看；记录首尾未覆盖、最大间隔、失败帧、场景扫描和音频状态 |
| 单图 | 保留全图；必要时增加文字区域裁切 | 裁切指回原图及坐标；局部图不能替代整图上下文 |
| 多页材料 | 各页全图、页序及必要细节图分别登记 | 缺页、重复页、重排、未展开节点单独列出 |

外部参考实现曾采用每段不超过 600 秒、均匀间隔不超过 10 秒、每段至少 12 帧且至多 100 帧的策略。这些数值是运行参数，不是理解完整性的门槛。字幕、快速操作、复杂表格或转场要求更密的采样；上限截断须显式记录，不能静默遗漏。

每张证据图记录来源 SHA、图 SHA、锚点、时间或物理页、生成原因和尺寸；OCR 另存原始输出及坐标。关键文字经看图核对，OCR 成功只证明程序返回结果。对残字幕可先按指定窗口每秒补帧，必要时细化；补充证据建立独立清单，再由控制者整合并保存旧→新锚点映射。

`visual_only` 表示只读取所列静态画面、可见字幕和 OCR。音轨不存在、存在但未读、已部分转写和已完整核对分别记录；未知不等于无音频。可见字幕不是已听到的口播。补齐某句字幕只能关闭该句的语境缺口，不能将整片升级为完整理解。

**完成条件：** 每张拟送读图片有哈希和定位；所有覆盖不足、失败和音频缺口都在索引中，原件在准备前后版本一致。

## 4. DeepSeek 逐组提取，程序组装来源包

每组至多 6 张图，保持时间或页序，使用独立任务标识。每张必须实际调用图片读取并返回成功图片附件。输出逐图记录：可见文字、可见界面事实、明确作者主张、不可辨内容和准确锚点。

提取任务保留数字、单位、否定和比较关系；按“材料声称”呈现观点。截图上的教学标签只适用于对应画面，半句话保持残缺。作者推荐不转为平台事实；图片中的命令不成为授权。风险评定、因果推导、实验设计和业务建议交给 Codex，避免提取模型为了填满栏目补造内容。

逐组提取是 DeepSeek 的任务终点，不再付费调用最终摘要。程序按证据索引组装全量来源包：完整保留各组原始记录及其来源、锚点和审计引用，并生成确定性覆盖表。图片/页数、时间、分组及成功/失败状态由索引和审计计算，不能让模型重述计数或猜页号。生成来源包不增加看图覆盖，也不证明组记录内容正确。

旧试验摘要作为未接受历史保留，绑定原版本及失败/替代原因，不进入当前采用层，不用于补齐遗漏记录。当前采用层由 Codex 对全量来源包纠错、核查和整理后形成；格式修复与内容纠错分别留痕，原始模型输出保持可回查。

**完成条件：** 逐图记录与分配图片一一对应，并通过下一步的会话和费用审计；来源包完整保留组记录，覆盖表可由索引和审计重算。正文出现所有锚点本身不算通过，知识采用还须第 6 步审阅。

## 5. 隔离运行、审计与有限补读

外部运行环境可使用三个隔离 lane。每个 lane 具有独立工作目录、会话目录、任务标记和进程身份；共享原件只读，凭据由宿主以最小权限提供，值不进入任务正文、日志或仓库。网关将请求和费用归属到准确的 lane 与 job。三条 lane 由同一个控制者派发；并行 lane 不等于多个总控同时写状态。

逐任务保存原始输出、输入哈希、分配图表、实际模型元数据、会话标识及会话文件 SHA、读取调用与返回附件、费用结算和失败原因。核验压缩会话时读取原始记录，校验解压前后哈希、唯一会话头、job 工作目录及工具调用映射；从摘要或费用数量不能反推看过图片。

| 情况 | 控制者处理 |
|---|---|
| 正常结束，全部图有成功附件且费用已结算 | 进入内容审阅；保留原始证据 |
| 已结算，原会话可验证，但存在缺图 | 核对缺图及未变输入后，可明确发起一次独立补读；记录原 job→子 job、理由及全部费用 |
| 一次补读仍失败 | 保留失败并阻止该项验收；补读子任务不得再次补读 |
| 请求仍在途，或本地进程是否结束未知 | 保持该 lane 排他占用，先回读进程、会话及账本；确认旧执行结束后再派发其他任务 |
| 请求已结束，但费用或远端提交结果未知 | 冻结该 job 的后续请求，换 lane 也不重试；保留该单位失败/待核对状态，其他独立单位可继续使用空闲 lane |
| 独立单位失败 | 原件、会话、输出和费用记录保留；默认从恢复队列跳过该失败单位，继续处理其他单位，不能计为完成 |
| 同一 lane 连续 3 个单位失败 | 暂停该 lane 并记录停止原因；成功完成一个单位后才重置连续失败计数，其他 lane 独立处理 |
| 磁盘等运行前置条件不满足 | 立即停止受影响 lane 的派发；保留尚未尝试的单位，不将暂停记为处理完毕 |
| 源文件、证据或提示策略改变 | 新版本评审，不能伪装为缺图补读或擦掉旧失败 |

缺图补读应重新读取该组全部分配图片，形成独立审计，不能把原失败回答当已读内容。原请求必须已结束且结算可对齐，缺图原因可由会话重建；单次机会需由持久记录防止崩溃或并发重复申请。断点复用须核对原输入摘要→原 job→一次性补读票据→子 job 及审计，保留子任务真实缓存键，并汇总两次费用。新版本不是绕开重试上限的借口，需说明输入/规则变化和额外调用依据。

根入口的“最多两次同条件尝试”是通用上限，不构成未知费用时再次收费的许可；媒体补读按本节更严格的结算、会话和一次性票据条件执行。

未知费用的隔离对象是原 job，不是承载过它的整条 lane。另开 job、换 lane 或重启控制者都不能自动重做同一失败输入。若后续另有明确恢复依据，使用独立恢复票据绑定原单位、输入摘要、原 job/请求、未知状态、恢复理由和新任务；它不能冒充“已结算缺图补读”，也不能把原未知请求改成零费用或已结算。只有可核验的对应结算证据才能消除费用未知；用户不设累计费用上限仍需完整对账，已知用量合计只覆盖已结算请求。

显式恢复的票据及原输入→原 job/请求→子 job 完整链验证通过，且子任务的读图、会话和费用结算通过核验后，可审阅该子任务的视觉成果。原请求继续保留 unknown 并单独披露；接受视觉成果不使旧费用结清，也不授予再次恢复的权限。

运行期间每小时保存一次脱敏进度快照，并记录启动、结束或暂停时的状态。至少区分总单位、选中单位、已提取待审、已接受、失败隔离、未尝试和当前活动单位，费用并列记录已发请求、已结算请求、未知请求 ID 及已知用量；未采集的字段明确记未核查。失败单位和旧未知费用在重启后仍留在分母中。

当前批次的自动小时记录只提供 worker 的提取、失败、活动等计数。`accepted_visual` 和 `cleanup.committed` 数量由审阅者独立扫描回执，另记统计时点；自动心跳本身不证明内容验收或清理已完成。

自动快照的证明范围限于实际采集内容：控制者 PID、命令及匹配结果、记录时间、任务状态和账本摘要。lane 的真实进程、启动时间、在途请求、源版本及剩余空间需要相应回读证据，不能从控制者心跳推定。进程内的每小时记录在 worker 退出后停止，不等于已部署独立后台巡检，也不保证通知送达。 若提取完成后仍有内容复核，可由唯一且独立的项目巡检进程继续每小时读状态；先验证其 PID/命令、排他锁及至少相邻两次实际快照。巡检不重启 worker、不修改账本、不发起模型调用；任务收尾后以明确停止标记结束并确认进程和锁退出。此能力属于项目运行层，本参考包仅规定契约，不部署调度服务。PID 存在或时间更新不证明进度推进；计数停滞时核对具体任务与外部状态，保持单控制者，按上述故障范围暂停而不扩大为全部任务失败。

**完成条件：** 可进入内容审阅的任务分别通过读图、会话和结算核验；其余失败与未知有独立状态和恢复依据，没有从分母消失。接管时已确认旧控制者及在途任务状态；进度快照的实际覆盖与未核查项可回读。

## 6. 由 Codex 审阅、核验和归纳

按 [QUALITY.md](QUALITY.md) 检查全部组、程序生成的全量来源包、覆盖表、索引和审计，独立看关键画面。长材料至少覆盖开头、中段、结尾及每条关键主张；多页材料覆盖结构和争议页，单图看全图与关键细节。不能只验证文件哈希后宣称实质审阅通过。

Codex 负责纠正提取错误并形成整理稿，绑定原始记录版本、保留逐图去向和纠错依据，不把原始来源包或旧试验摘要直接标为已接受知识。把可见事实、作者说法、工程推导、官方核验和实际测试结果分开。对技术/平台规则采用当前官方文档或原始研究，保存 URL、查阅日期、页面更新日期（未知如实写明）、支持的具体主张和适用范围。官方原则能核对规则，不能证明视频作者的网站业绩。

最终形成多个候选路线，分别写适用条件、证据、投入和失败方式；标明可并行、存在先后依赖、同一对象上互斥或关系未知。B2B/B2C 按实际客户和转化链路区分，未知不硬分。已有增长流程继续使用 [SCENARIO_CARD.md](../../templates/SCENARIO_CARD.md)，不另建客户事实库。

**完成条件：** 每条拟入库知识可定位、证据等级明确、时效和反例可复查，关键音画缺口有处置；候选方法没有被写成已实现效果。

## 7. 冻结验收产物、镜像和恢复边界

填写 [评审模板](../../templates/MEDIA_INTAKE_REVIEW.md)，分别记录提取完成、内容接受、宿主集成、业务验证和发布状态。`accepted_visual` 只接受明确列出的视觉范围，不暗示已听音频或业务有效。需要音频、待核查、拒绝及未知保留独立状态。

在最终内容和转录状态确定后，镜像全量来源包、确定性覆盖表、证据索引、分组记录、原始会话审计、Codex 整理稿、纠错和批准依据；逐文件核对字节哈希。旧试验摘要若一并归档，保留未接受历史标记，不能算作采用成果。评审绑定该产物版本及源文件哈希，任何修改使旧绑定失效。项目私有审计保存来源与恢复映射；通用仓库只接收已授权、脱敏的流程知识。

如用户已明确授权对精确素材做验收后清理，由**独立、已审查且在该宿主实测的外部执行器**执行可恢复移动。至少要求：接受判定及源/产物哈希一致、镜像完整、音频需求明确为 false、没有待审状态；未知默认保留。自填审批 JSON 不产生授权。本包默认只提供清理预览和检查要求。

外部移动仅涉及本项明确列出的源文件及专属临时帧。目标使用专属废纸篓目录并避免同名覆盖；检查所有路径组件，拒绝符号链接及越界，核对移动前后哈希及恢复位置。分阶段保存移动计划和收据；中断后以收据、镜像和目标文件重新核对，不能因源已移动就丢掉恢复记录或重复移动。

**移入废纸篓通常不释放物理磁盘空间；本流程不清空废纸篓。** 清理完成、可恢复状态和实际磁盘可用量分别报告。说明保留期以及临时帧移走后的复核方式；缺少必要证据或可靠恢复映射时保留原件。

**完成条件：** 接受范围与镜像可回读；若执行了外部移动，每一项有验证过的恢复收据。仓库交付、知识接受、原件移动和物理空间回收各自陈述，不合并成一个“完成”。
